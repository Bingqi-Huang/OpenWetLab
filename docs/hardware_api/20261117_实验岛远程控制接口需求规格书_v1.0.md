# 实验岛远程控制接口需求规格书



## 1. 总体要求

### 1.1 功能对等原则

1. GUI 程序块面板中的**每一个程序块**，都必须对应至少一个可通过接口调用的"动作"。
2. GUI 中程序块能设置的**每一个参数**，接口都必须能设置，含义、单位、取值范围一致。
3. GUI 中能看到的**每一个状态和数据**（设备状态、温度、剩余时间、料位占用、报警、运行日志、仪器结果文件），接口都必须能读到。
4. GUI 中能做的**每一种人工操作**（注册物料、启动、暂停、继续、停止、清除报警、复位），接口都必须能做。


### 1.2 单个动作必须可以独立调用

接口必须支持**一次只执行一个程序块**（例如只把一块板从 A 位搬到 B 位，或只运行一次 PCR），由我方软件自行决定先后顺序和参数。不允许只提供"启动一条预先编好的完整流程"这一种方式。

预先编好的完整流程也必须可以启动（见 4.8），但它是补充，不能替代单个动作。

### 1.3 术语对照

| 本文用词 | 英文字段 | 对应硬件方现有概念 |
|---|---|---|
| 设备 | device | 岛上的一台仪器或机构：机械臂、PCR 仪、摇床、离心机、料盘库等 |
| 动作 | action | 一个程序块能做的一件事 |
| 料位 | position | 已注册并已示教、可以放物料的一个位置 |
| 物料 | labware | 可以被机械臂搬运的一件东西：孔板、PCR 板、管架、吸头盒等 |
| 流程 | workflow | 在 GUI 中用程序块编好并保存的一条流程 |
| 操作 | operation | 一次具体的执行。每次执行有唯一的 `operation_id` |

### 1.4 职责边界

| 事项 | 负责方 |
|---|---|
| 示教、料位注册、运动轨迹、碰撞规避 | 硬件方 |
| 安全互锁、急停、限位、设备保护 | 硬件方 |
| 执行前检查（设备是否空闲、料位是否有料、盖是否打开等） | 硬件方（接口必须拒绝不安全的请求并返回明确错误码） |
| 决定做什么实验、动作顺序、参数取值 | 我方 |
| 样品信息、实验记录、数据分析 | 我方 |

机械臂只在已示教的料位之间运动。我方永远只传料位编号，不传坐标。

## 2. 通用约定

### 2.1 协议与地址

- 协议：HTTP/1.1，请求体和响应体均为 JSON，编码 UTF-8。
- 地址：`http://<控制电脑IP>:<端口>/api/v1`。IP 必须固定。
- 服务必须随控制电脑开机自动启动，持续运行，无需人工登录或点击。
- 服务监听局域网地址（不能只监听 127.0.0.1）。

### 2.2 鉴权

每个请求带请求头 `X-API-Key: <密钥>`。密钥在硬件方配置文件中设置。缺失或错误返回 HTTP 401。

### 2.3 数据格式

- 时间：ISO 8601 带时区，例如 `2026-11-17T15:30:05.123+08:00`。控制电脑必须开启网络对时。
- 编号（ID）：全部为字符串，一经分配不得改变、不得重复使用。
- 字段名：小写加下划线。带单位的数值必须把单位写进字段名。

| 物理量 | 单位 | 字段后缀示例 |
|---|---|---|
| 温度 | 摄氏度 | `temp_c` |
| 时间长度 | 秒 | `duration_s` |
| 转速 | 转/分 | `speed_rpm` |
| 离心力 | ×g | `rcf_g` |
| 体积 | 微升 | `volume_ul` |
| 曝光时间 | 毫秒 | `exposure_ms` |
| 百分比 | % | `co2_pct` |
| 长度 | 毫米 | `offset_mm` |

### 2.4 HTTP 状态码

| 状态码 | 含义 |
|---|---|
| 200 | 成功 |
| 202 | 操作已接收，正在排队或执行 |
| 400 | 请求格式错误（不是合法 JSON、缺少必填字段） |
| 401 | 密钥错误 |
| 404 | 编号不存在 |
| 409 | 请求合法但当前不能执行（设备忙、料位被占、处于本地模式等） |
| 422 | 参数值不合法（超范围、类型不对） |
| 500 | 服务内部错误 |

### 2.5 统一错误格式

所有非 2xx 响应的响应体必须是：

```json
{
  "error": {
    "code": "DEVICE_BUSY",
    "message": "PCR仪 pcr-1 正在执行操作 op-000118",
    "device_id": "pcr-1",
    "vendor_code": "E2031",
    "recoverable": true,
    "recovery_hint": "等待当前操作结束后重试",
    "detail": {}
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `code` | 是 | 第 7 章规定的错误码 |
| `message` | 是 | 中文说明，要写清是哪台设备、哪个料位、什么原因 |
| `device_id` | 否 | 相关设备 |
| `vendor_code` | 否 | 硬件方内部原始故障码 |
| `recoverable` | 是 | 不需要人到现场处理就能恢复为 `true`，否则 `false` |
| `recovery_hint` | 否 | 建议的处理方法 |
| `detail` | 否 | 其他补充信息 |

### 2.6 性能与可靠性

1. 所有查询接口（GET）响应时间不超过 500 毫秒。
2. 所有提交接口（POST）在 1 秒内返回，**不等待设备动作完成**。
3. 设备实际状态发生变化后，1 秒内接口查询结果必须反映该变化。
4. 支持每秒不少于 20 次请求，支持不少于 5 个客户端同时访问。
5. 操作记录、事件记录、物料和料位状态必须保存到磁盘，软件或电脑重启后不丢失，至少保留 90 天。
6. 我方网络断开不得影响正在执行的操作，操作必须继续执行到结束，网络恢复后可以查询到结果。

### 2.7 版本

接口上线后，字段只允许增加，不允许删除、改名或改变含义。必须修改时使用新路径 `/api/v2`，旧版本保留不少于 3 个月。

## 4. 接口详细定义

### 4.1 系统

#### S1 `GET /system/info`

```json
{
  "island_id": "island-01",
  "island_name": "一号实验岛",
  "software_name": "XXX 控制软件",
  "software_version": "3.2.1",
  "api_version": "1.0.0",
  "server_time": "2026-11-17T15:30:05.123+08:00"
}
```

#### S2 `GET /system/status`

```json
{
  "state": "ready",
  "mode": "remote",
  "estop_active": false,
  "interlock_ok": true,
  "active_alarm_count": 0,
  "running_operation_ids": ["op-000118"],
  "latest_event_seq": 48211,
  "server_time": "2026-11-17T15:30:05.123+08:00"
}
```

| 字段 | 取值 | 说明 |
|---|---|---|
| `state` | `initializing` / `ready` / `busy` / `alarm` / `estop` | 整岛状态 |
| `mode` | `remote` / `local` | 远程模式下接口可以下发动作；本地模式下只有现场 GUI 可以（见 5.7） |
| `estop_active` | 布尔 | 急停是否按下 |
| `interlock_ok` | 布尔 | 安全门等互锁是否全部正常 |

### 4.2 设备

#### D1 `GET /devices`

返回岛上**全部**设备。

```json
{
  "devices": [
    {
      "device_id": "arm-1",
      "name": "转运机械臂",
      "type": "arm",
      "model": "厂商型号",
      "status": "idle",
      "current_operation_id": null,
      "position_ids": [],
      "action_names": ["arm.transfer", "arm.home", "arm.initialize", "arm.reset"],
      "readings": {"gripper_holding": false}
    },
    {
      "device_id": "pcr-1",
      "name": "PCR仪1号",
      "type": "pcr",
      "model": "厂商型号",
      "status": "busy",
      "current_operation_id": "op-000118",
      "position_ids": ["pcr-1-block"],
      "action_names": ["pcr.open_lid", "pcr.close_lid", "pcr.run", "pcr.set_block_temp", "pcr.initialize", "pcr.reset"],
      "readings": {
        "block_temp_c": 94.8,
        "lid_temp_c": 105.0,
        "lid_open": false,
        "current_stage": 2,
        "current_cycle": 12,
        "total_cycles": 35,
        "remaining_s": 2710
      }
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `device_id` | 是 | 设备编号，固定不变 |
| `type` | 是 | 设备类型，取值见第 6 章 |
| `status` | 是 | `idle` 空闲 / `busy` 执行中 / `alarm` 报警 / `offline` 通信断开 / `initializing` 初始化中 / `disabled` 已停用 |
| `current_operation_id` | 是 | 正在执行的操作，空闲时为 `null` |
| `position_ids` | 是 | 属于该设备的料位 |
| `action_names` | 是 | 该设备支持的全部动作 |
| `readings` | 是 | 实时读数。GUI 上能看到的读数必须全部列出，字段名带单位 |

#### D2 `GET /devices/{device_id}`

返回单台设备，格式同上面列表中的一项。

### 4.3 动作目录

#### A1 `GET /actions`

返回**全部**动作的定义。我方软件依据这份目录自动生成调用代码，所以它必须完整、准确，并与实际行为一致。

```json
{
  "actions": [
    {
      "name": "shaker.run",
      "title": "振荡",
      "description": "按设定转速和时间振荡，结束后自动停止并回到可取放位置",
      "device_type": "shaker",
      "device_ids": ["shaker-1"],
      "gui_block_name": "摇晃",
      "params_schema": {
        "type": "object",
        "required": ["speed_rpm", "duration_s"],
        "properties": {
          "speed_rpm": {"type": "integer", "minimum": 100, "maximum": 2000, "description": "转速"},
          "duration_s": {"type": "integer", "minimum": 1, "maximum": 86400, "description": "时长"},
          "temp_c": {"type": "number", "minimum": 4, "maximum": 70, "description": "温度，不填则不控温"}
        }
      },
      "result_schema": {
        "type": "object",
        "properties": {
          "actual_duration_s": {"type": "integer"},
          "actual_speed_rpm": {"type": "integer"}
        }
      },
      "preconditions": ["设备空闲", "料位 shaker-1-pos 上有物料"],
      "effects": ["不改变物料位置"],
      "typical_duration_s": null,
      "cancellable": true,
      "pausable": true,
      "produces_artifacts": false,
      "error_codes": ["DEVICE_BUSY", "POSITION_EMPTY", "HARDWARE_FAULT"]
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 动作名，格式 `设备类型.动词`，全小写。命名见第 6 章 |
| `title` / `description` | 是 | 中文名称和说明，说明要写清动作结束后设备处于什么状态 |
| `device_ids` | 是 | 哪些设备可以执行该动作 |
| `gui_block_name` | 是 | 对应的 GUI 程序块名称 |
| `params_schema` | 是 | 参数定义，JSON Schema 格式。每个参数必须有类型、中文说明；数值必须有最小值和最大值；枚举必须列出全部可选值；必填项列入 `required` |
| `result_schema` | 是 | 执行成功后返回结果的定义，JSON Schema 格式 |
| `preconditions` | 是 | 执行前必须满足的条件，逐条列出 |
| `effects` | 是 | 执行后的变化：物料位置是否改变、盖是否打开、设备是否自动执行了其他附带动作 |
| `typical_duration_s` | 是 | 典型耗时。由参数决定的填 `null` |
| `cancellable` / `pausable` | 是 | 是否支持停止、暂停 |
| `produces_artifacts` | 是 | 是否产生数据文件 |
| `error_codes` | 是 | 可能返回的错误码 |

#### A2 `GET /actions/{action_name}`

返回单个动作定义，格式同上。

### 4.4 料位

#### P1 `GET /positions`

返回**全部**已注册料位。可选查询参数：`device_id`、`occupied=true|false`。

```json
{
  "positions": [
    {
      "position_id": "hotel-1-03",
      "name": "料盘库1 第3层",
      "type": "storage",
      "device_id": "hotel-1",
      "accepts_labware_types": ["plate_96", "pcr_plate_96"],
      "occupied_by": "lw-000042",
      "arm_reachable": true,
      "enabled": true
    },
    {
      "position_id": "pcr-1-block",
      "name": "PCR仪1号 加热模块",
      "type": "device",
      "device_id": "pcr-1",
      "accepts_labware_types": ["pcr_plate_96"],
      "occupied_by": null,
      "arm_reachable": true,
      "enabled": true
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `position_id` | 是 | 料位编号，固定不变 |
| `type` | 是 | `storage` 存储位 / `device` 设备工位 / `transfer` 中转位 / `io` 人工上下料口 / `waste` 废弃位 |
| `device_id` | 否 | 所属设备，不属于任何设备填 `null` |
| `accepts_labware_types` | 是 | 能放哪些类型的物料 |
| `occupied_by` | 是 | 当前放着的物料编号，空位为 `null` |
| `arm_reachable` | 是 | 机械臂是否已示教可达 |
| `enabled` | 是 | 是否可用 |

**要求：** 所有 `arm_reachable` 为 `true` 的料位之间，机械臂必须能够任意两两转运（只要目标料位接受该类型物料）。如存在不能直接转运的料位组合，必须在交付文档中逐一列出，并在 `arm.transfer` 中返回 `PRECONDITION_FAILED`。

### 4.5 物料

#### L1 `GET /labware-types`

```json
{
  "labware_types": [
    {"type": "pcr_plate_96", "name": "96孔PCR板", "rows": 8, "columns": 12, "max_volume_ul": 200, "has_lid": false},
    {"type": "plate_96", "name": "96孔板", "rows": 8, "columns": 12, "max_volume_ul": 360, "has_lid": true}
  ]
}
```

#### L2 `GET /labware`　L3 `GET /labware/{labware_id}`

L2 可选查询参数：`position_id`、`type`、`barcode`。

```json
{
  "labware_id": "lw-000042",
  "type": "pcr_plate_96",
  "barcode": "PCR20261117001",
  "position_id": "hotel-1-03",
  "location_state": "at_position",
  "lid_on": false,
  "metadata": {"experiment_id": "exp-0007", "note": "样品板A"},
  "registered_at": "2026-11-17T14:02:11+08:00",
  "updated_at": "2026-11-17T14:02:11+08:00"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `labware_id` | 是 | 物料编号，由硬件方在登记时分配，或采用我方在登记时传入的编号 |
| `type` | 是 | 物料类型，取自 L1 |
| `barcode` | 否 | 条码。岛上有扫码器时必须填实际扫到的值 |
| `position_id` | 是 | 当前所在料位。不在任何料位上时为 `null` |
| `location_state` | 是 | `at_position` 在料位上 / `in_transit` 机械臂夹持中 / `unknown` 位置不确定需人工核对 |
| `lid_on` | 否 | 是否带盖 |
| `metadata` | 是 | 我方写入的任意 JSON，硬件方原样保存、原样返回，不解析 |

**要求：** 物料位置必须始终反映现场实际情况。无论物料是被接口下发的动作移动，还是被现场 GUI 操作移动，这里都必须同步更新。

#### L4 `POST /labware` —— 登记物料

人把一块板放到某个料位后，通过此接口告诉系统。等同于 GUI 中的"注册物料"。

请求：

```json
{
  "labware_id": "lw-000042",
  "type": "pcr_plate_96",
  "position_id": "hotel-1-03",
  "barcode": "PCR20261117001",
  "lid_on": false,
  "metadata": {"experiment_id": "exp-0007"}
}
```

`labware_id` 可不传，由硬件方分配。成功返回 200 和完整物料对象。料位已被占用返回 409 `POSITION_OCCUPIED`；料位不接受该类型返回 409 `LABWARE_INCOMPATIBLE`；编号重复返回 409 `LABWARE_ID_EXISTS`。

#### L5 `PATCH /labware/{labware_id}` —— 修改或人工更正

请求体只包含要修改的字段，可修改 `position_id`、`barcode`、`lid_on`、`metadata`。用于故障后人工把物料放回并更正位置。成功返回 200 和完整物料对象。

#### L6 `DELETE /labware/{labware_id}` —— 注销

物料已被人从岛上取走。成功返回 200，对应料位变为空。物料在机械臂夹持中时返回 409 `PRECONDITION_FAILED`。

### 4.6 执行一个动作

#### O1 `POST /operations`

请求：

```json
{
  "request_id": "7f3c1c1e-2b1a-4e0e-9a55-1f6f5f1f0a01",
  "action": "arm.transfer",
  "device_id": "arm-1",
  "params": {
    "labware_id": "lw-000042",
    "source_position_id": "hotel-1-03",
    "destination_position_id": "shaker-1-pos"
  },
  "validate_only": false
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `request_id` | 是 | 我方生成的唯一编号，用于防止重复执行（见 5.2） |
| `action` | 是 | 动作名 |
| `device_id` | 是 | 执行该动作的设备 |
| `params` | 是 | 动作参数，必须符合该动作的 `params_schema` |
| `validate_only` | 否 | 为 `true` 时只做全部检查，不执行、不产生操作记录，返回 200 `{"valid": true}` 或对应错误 |

处理要求：

1. 收到请求后**立即**完成参数检查和执行前检查（见 5.4），1 秒内返回。
2. 检查通过：返回 HTTP 202 和操作对象，`status` 为 `queued` 或 `running`。
3. 检查不通过：返回 4xx 和错误对象，**设备不得有任何动作**。

响应（202）：操作对象，定义见 4.9。

### 4.7 连续执行一串动作

#### O2 `POST /sequences`

用于必须紧密衔接的动作（例如 PCR 结束后立刻取板）。硬件方在现场按顺序连续执行，中间不等待我方指令。

请求：

```json
{
  "request_id": "9a1e0b7c-6f0d-4a7b-8c11-2d2b7b9e4c02",
  "name": "PCR后取板",
  "steps": [
    {"action": "pcr.open_lid", "device_id": "pcr-1", "params": {}},
    {"action": "arm.transfer", "device_id": "arm-1",
     "params": {"labware_id": "lw-000042", "source_position_id": "pcr-1-block", "destination_position_id": "hotel-1-03"}},
    {"action": "pcr.close_lid", "device_id": "pcr-1", "params": {}}
  ]
}
```

处理要求：

1. 提交时对**所有**步骤做参数检查，任何一步不合法则整体拒绝，返回 422，不执行任何步骤。
2. 按顺序执行，上一步成功后立即开始下一步。
3. 任何一步失败则立即停止，后续步骤状态记为 `skipped`，整个操作状态为 `failed`。
4. 返回 HTTP 202 和操作对象，其中 `kind` 为 `sequence`，`steps` 列出每一步的状态和结果。

#### O5 `GET /operations/{operation_id}`

返回操作对象。操作结束后仍可查询，至少保留 90 天。

#### O6 `GET /operations`

查询参数：`status`、`device_id`、`request_id`、`since`（开始时间）、`limit`（默认 50，最大 500）。按创建时间倒序返回 `{"operations": [ ... ]}`。

必须包含由现场 GUI 发起的操作。

#### O7 `POST /operations/{operation_id}/cancel` —— 停止

1. 设备必须停到安全状态。机械臂正在搬运时，必须把物料放到一个确定的料位（目标位或原位）再停，不得夹着物料悬停。
2. 停止完成后操作状态为 `cancelled`，物料位置必须已更新为实际位置。
3. 立即返回 200 和操作对象（此时状态可能仍为 `running`，停止完成后变为 `cancelled`）。
4. 操作已结束返回 409 `OPERATION_FINISHED`；动作不支持停止返回 409 `NOT_CANCELLABLE`。

行为与 GUI 中的暂停、继续一致。暂停后状态为 `paused`，继续后为 `running`。不支持暂停的动作返回 409 `NOT_PAUSABLE`。

## 5. 行为规则

### 5.1 操作状态

```
queued ──> running ──> succeeded
              │  ▲
              ▼  │
            paused
              │
running/paused ──> failed
running/paused/queued ──> cancelled
queued/running/paused ──> manual_check
```

| `status` | 含义 | 是否结束 |
|---|---|---|
| `queued` | 已接收，尚未开始 | 否 |
| `running` | 设备正在执行 | 否 |
| `paused` | 已暂停 | 否 |
| `succeeded` | 设备**实际**完成了动作 | 是 |
| `failed` | 执行失败，`error` 中有原因 | 是 |
| `cancelled` | 已被停止 | 是 |
| `manual_check` | 硬件方无法确定动作是否完成（例如执行中软件重启），需要人到现场核对 | 是 |

要求：

1. `succeeded` 必须以设备的实际反馈为准（到位信号、温度程序实际跑完），不得以"指令已发出"作为成功。
2. 进入结束状态后不得再变化。
3. 不确定时必须报 `manual_check`，不得猜测为成功或失败。

### 5.2 防止重复执行

网络不稳定时，我方可能把同一个请求发送多次。硬件方必须保证设备只动作一次：

1. 每个提交请求带 `request_id`。硬件方必须把 `request_id` 和对应的 `operation_id` 保存到磁盘，至少保留 90 天。
2. 收到一个**已经见过**的 `request_id`，且请求内容相同：**不执行**，直接返回 HTTP 200 和原来那次操作的当前状态。
3. 收到一个已经见过的 `request_id`，但请求内容不同：返回 409 `REQUEST_ID_CONFLICT`，不执行。
4. 该规则在软件重启后依然有效。

### 5.3 多台设备同时工作

1. 不同设备必须可以同时执行各自的操作。例如 PCR 仪运行期间，机械臂可以搬运其他板，摇床可以同时振荡。
2. 同一台设备正在执行时收到新的操作：返回 409 `DEVICE_BUSY`，**不自动排队**。
3. 两个操作需要同一个料位或会发生干涉：后到的返回 409 及相应错误码。

### 5.4 执行前检查

提交操作时，硬件方必须立即检查以下内容，任何一项不满足则拒绝并返回对应错误码，设备不得有任何动作：

| 检查内容 | 错误码 |
|---|---|
| 整岛处于远程模式 | `LOCAL_MODE` |
| 急停未按下 | `ESTOP_ACTIVE` |
| 互锁正常 | `INTERLOCK_OPEN` |
| 设备存在 | `UNKNOWN_DEVICE` |
| 动作存在且该设备支持 | `UNKNOWN_ACTION` |
| 参数类型和范围合法 | `INVALID_PARAMS` |
| 设备在线、已初始化 | `DEVICE_NOT_READY` |
| 设备无报警 | `DEVICE_ALARM` |
| 设备空闲 | `DEVICE_BUSY` |
| 涉及的料位、物料存在 | `UNKNOWN_POSITION` / `UNKNOWN_LABWARE` |
| 源料位上确实是指定的物料 | `POSITION_EMPTY` / `LABWARE_MISMATCH` |
| 目标料位为空 | `POSITION_OCCUPIED` |
| 目标料位接受该类型物料 | `LABWARE_INCOMPATIBLE` |
| 动作的其他前提（盖已打开、门已关闭、离心已配平等） | `PRECONDITION_FAILED`（`message` 中写明具体是哪一条） |

动作**不得隐式执行**未声明的附带动作。如果某个动作会自动开盖、自动关门，必须写在该动作的 `effects` 中。

### 5.5 失败后的状态

操作失败后：

1. `error` 必须说明：哪台设备、哪一步、什么原因、是否需要人到现场。
2. 涉及的每件物料的位置必须更新为实际情况。无法确定时 `location_state` 置为 `unknown`。
3. 设备状态必须反映实际情况（`alarm` 或 `idle`）。
4. 必须同时产生报警记录和事件。
5. 不得自动重试会移动物料的动作。

### 5.6 重启与断线

1. 我方网络断开：正在执行的操作继续执行到结束，记录完整保留。
2. 硬件方软件或控制电脑重启后：
   - 历史操作、事件、物料和料位状态全部保留。
   - 重启时正在执行的操作：能从设备确认已完成的记为 `succeeded`，能确认未完成的记为 `failed`，无法确认的记为 `manual_check`。
   - **不得**自动重新执行任何操作。
   - 重启完成前 `system.state` 为 `initializing`。

### 5.7 远程模式与本地模式

1. GUI 上必须有"远程 / 本地"切换。
2. 远程模式：接口可以下发操作。
3. 本地模式：所有查询接口正常工作；所有会让设备动作的接口返回 409 `LOCAL_MODE`。
4. 从远程切到本地时，正在执行的操作按 GUI 现有规则处理（继续或停止），结果如实反映在操作状态中。
5. 现场人员在 GUI 上做的任何操作，都必须产生对应的操作记录（`source` 为 `gui`）和事件，物料位置同步更新。

### 5.8 急停与互锁

1. 急停和互锁完全由硬件方现有逻辑处理，优先级高于接口的任何请求。
2. 急停或互锁触发后：正在执行的操作状态变为 `failed`，错误码为 `ESTOP_TRIGGERED` 或 `INTERLOCK_TRIGGERED`；物料位置按 5.5 更新。
3. 急停释放后不得自动恢复执行。

## 6. 必须提供的动作

### 6.1 规则

1. 岛上有的每一种设备，必须提供下表列出的全部动作。
2. 下表之外，GUI 程序块面板中还有的其他程序块，必须按相同格式一并提供（1.1 功能对等原则）。
3. 下表给出的是**最少**参数。设备和 GUI 实际支持的其他参数必须全部补充进 `params_schema`。
4. 动作名、参数名按下表执行。新增动作命名格式为 `设备类型.动词`。
5. 每一种设备都必须提供 `<类型>.initialize`（初始化 / 回原点）和 `<类型>.reset`（故障复位）。

### 6.2 机械臂 `arm`

| 动作 | 参数 | 结果 | 说明 |
|---|---|---|---|
| `arm.transfer` | `labware_id`、`source_position_id`、`destination_position_id` | `labware_id`、`position_id` | 把指定物料从一个料位搬到另一个料位。对应"上料""返回料"及所有转运类程序块 |
| `arm.remove_lid` | `labware_id`、`lid_position_id` | — | 取下板盖放到指定料位。物料带盖时必须提供 |
| `arm.replace_lid` | `labware_id`、`lid_position_id` | — | 盖回板盖 |
| `arm.home` | 无 | — | 回到安全待机位 |

`arm.transfer` 成功后，物料的 `position_id` 必须已更新为目标料位。岛上有扫码器时，结果中必须包含实际扫到的 `barcode`，与登记条码不一致时失败并返回 `LABWARE_MISMATCH`。

| `storage.open_door` / `storage.close_door` | 无 | — | 存储设备有门时必须提供 |

| 动作 | 参数 | 结果 | 说明 |
|---|---|---|---|
| `io.open` / `io.close` | 无 | — | 打开、关闭上下料口 |
| `io.request_load` | `position_id`、`labware_type`、`message` | `labware_id` | 提示现场人员放入物料，人员确认后完成 |
| `io.request_unload` | `labware_id`、`message` | — | 提示现场人员取走物料，人员确认后完成并自动注销 |

### 6.5 PCR 仪 / 热循环仪 `pcr`

| 动作 | 参数 | 结果 | 说明 |
|---|---|---|---|
| `pcr.open_lid` | 无 | — | 开盖 |
| `pcr.close_lid` | 无 | — | 关盖 |
| `pcr.run` | `program`（见下）、`sample_volume_ul` | `completed`、`actual_duration_s`、数据文件 | 运行一次完整的温度程序 |
| `pcr.set_block_temp` | `temp_c`、`duration_s`（不填则一直保持）、`lid_temp_c` | — | 恒温保持 |

`program` 结构（温度程序必须完全由参数指定，**不允许**只能选择仪器上预存的程序编号）：

```json
{
  "lid_temp_c": 105,
  "stages": [
    {"cycles": 1,  "steps": [{"temp_c": 95, "hold_s": 180}]},
    {"cycles": 35, "steps": [
      {"temp_c": 95, "hold_s": 15},
      {"temp_c": 58, "hold_s": 30},
      {"temp_c": 72, "hold_s": 45, "read": false}
    ]},
    {"cycles": 1,  "steps": [{"temp_c": 72, "hold_s": 300}]}
  ],
  "final_hold_temp_c": 4
}
```

每一步可选参数：`ramp_c_per_s`（升降温速率）、`read`（定量 PCR 是否在该步采集荧光）、以及仪器支持的梯度、递增等参数。

`pcr.run` 必须产生的数据文件：运行日志（实际温度随时间的记录）。定量 PCR 仪还必须提供原始荧光数据和仪器导出文件。

实时读数（`readings`）必须包含：`block_temp_c`、`lid_temp_c`、`lid_open`、`current_stage`、`current_cycle`、`total_cycles`、`remaining_s`。

## 8. 完整示例

目标：把一块 PCR 板从料盘库取出，振荡 60 秒，运行 PCR，结束后放回料盘库。全程不触碰 GUI。

**第 1 步：确认整岛可用**

```
GET /api/v1/system/status
→ 200 {"state": "ready", "mode": "remote", "estop_active": false, "interlock_ok": true, ...}
```

**第 2 步：登记人工放入的板**

```
POST /api/v1/labware
{"type": "pcr_plate_96", "position_id": "hotel-1-03", "metadata": {"experiment_id": "exp-0007"}}
→ 200 {"labware_id": "lw-000042", "position_id": "hotel-1-03", "location_state": "at_position", ...}
```

**第 3 步：搬到摇床**

```
POST /api/v1/operations
{"request_id": "r-001", "action": "arm.transfer", "device_id": "arm-1",
 "params": {"labware_id": "lw-000042", "source_position_id": "hotel-1-03", "destination_position_id": "shaker-1-pos"}}
→ 202 {"operation_id": "op-000115", "status": "queued", ...}

GET /api/v1/operations/op-000115
→ 200 {"operation_id": "op-000115", "status": "running", ...}
→ 200 {"operation_id": "op-000115", "status": "succeeded", "result": {"labware_id": "lw-000042", "position_id": "shaker-1-pos"}, ...}
```

**第 4 步：振荡**

```
POST /api/v1/operations
{"request_id": "r-002", "action": "shaker.run", "device_id": "shaker-1",
 "params": {"speed_rpm": 800, "duration_s": 60}}
→ 202 {"operation_id": "op-000116", "status": "running", ...}
（查询直到 succeeded）
```

**第 5 步：开盖，搬到 PCR 仪，关盖**

```
POST /api/v1/sequences
{"request_id": "r-003", "name": "装载PCR",
 "steps": [
   {"action": "pcr.open_lid", "device_id": "pcr-1", "params": {}},
   {"action": "arm.transfer", "device_id": "arm-1",
    "params": {"labware_id": "lw-000042", "source_position_id": "shaker-1-pos", "destination_position_id": "pcr-1-block"}},
   {"action": "pcr.close_lid", "device_id": "pcr-1", "params": {}}
 ]}
→ 202 {"operation_id": "op-000117", "kind": "sequence", "status": "running", "steps": [...]}
（查询直到 succeeded）
```

**第 6 步：运行 PCR**

```
POST /api/v1/operations
{"request_id": "r-004", "action": "pcr.run", "device_id": "pcr-1",
 "params": {"sample_volume_ul": 20, "program": {"lid_temp_c": 105, "stages": [
   {"cycles": 1,  "steps": [{"temp_c": 95, "hold_s": 180}]},
   {"cycles": 35, "steps": [{"temp_c": 95, "hold_s": 15}, {"temp_c": 58, "hold_s": 30}, {"temp_c": 72, "hold_s": 45}]},
   {"cycles": 1,  "steps": [{"temp_c": 72, "hold_s": 300}]}
 ], "final_hold_temp_c": 4}}}
→ 202 {"operation_id": "op-000118", "status": "running", ...}

GET /api/v1/operations/op-000118
→ 200 {"status": "running", "progress": {"percent": 34, "message": "第2阶段 循环 12/35", "remaining_s": 2710}, ...}
...
→ 200 {"status": "succeeded",
       "result": {"completed": true, "actual_duration_s": 4512},
       "artifacts": [{"artifact_id": "af-000301", "name": "pcr-1_20261117_150200_runlog.csv", "kind": "run_log", ...}], ...}
```

PCR 运行期间，我方可以同时向 `arm-1`、`shaker-1` 提交其他板的操作，硬件方必须正常执行。

**第 7 步：下载运行日志**

```
GET /api/v1/artifacts/af-000301
→ 200 （CSV 文件内容）
```

**第 8 步：取板放回料盘库**

```
POST /api/v1/sequences
{"request_id": "r-005", "name": "PCR后取板",
 "steps": [
   {"action": "pcr.open_lid", "device_id": "pcr-1", "params": {}},
   {"action": "arm.transfer", "device_id": "arm-1",
    "params": {"labware_id": "lw-000042", "source_position_id": "pcr-1-block", "destination_position_id": "hotel-1-03"}},
   {"action": "pcr.close_lid", "device_id": "pcr-1", "params": {}}
 ]}
→ 202 {"operation_id": "op-000119", ...}
（查询直到 succeeded）

GET /api/v1/labware/lw-000042
→ 200 {"position_id": "hotel-1-03", "location_state": "at_position", ...}
```

**出错时的例子：目标料位已被占用**

```
POST /api/v1/operations
{"request_id": "r-006", "action": "arm.transfer", "device_id": "arm-1",
 "params": {"labware_id": "lw-000043", "source_position_id": "hotel-1-04", "destination_position_id": "pcr-1-block"}}
→ 409 {"error": {"code": "POSITION_OCCUPIED", "message": "料位 pcr-1-block 上已有物料 lw-000042",
                 "device_id": "pcr-1", "recoverable": true, "recovery_hint": "先移走该物料"}}
```

机械臂不得有任何动作。
