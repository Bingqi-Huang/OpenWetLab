# 黑灯实验室外部业务系统首期对接方案

| 文档项 | 内容 |
| --- | --- |
| 文档版本 | V1.0 |
| 文档状态 | 评审稿 |
| 编制日期 | 2026-11-17 |
| 适用系统 | 用户业务系统、黑灯实验室服务端 |
| 首期目标 | 在用户系统完成物料登记、工艺编排、实验订单创建与执行，并获取执行状态和实验结果 |
| 对接方式 | HTTP REST API + Swagger / OpenAPI 3 + 异步事件回调 |

> 本文中的 `/openapi/lab/v1/**` 为规划新增的对外接口，并非当前已经上线的接口。现有内部接口仅作为实现基础，不建议直接全部对外开放。

## 1. 项目背景

用户已有一套业务系统，需要在不重复建设实验室调度能力的前提下，与黑灯实验室系统对接，实现：

1. 在用户系统中登记实验物料。
2. 根据实验室提供的组件库编排工艺流程。
3. 创建实验任务订单并绑定工艺和物料。
4. 将订单下发到黑灯实验室系统执行。
5. 查询或接收任务状态、异常信息和实验结果。

黑灯实验室系统继续负责设备、位置、工艺执行、物料流转、任务调度和设备通信；用户系统负责业务页面、业务单据及用户侧流程管理。

## 2. 现状与可行性判断

### 2.1 已具备的基础能力

经现有代码静态核查，服务端已经具备：

- 设备列表、设备详情、在线状态和运行时状态查询。
- 物料单个新增、批量新增、物料类校验、位置校验和占用处理。
- 工艺草稿创建、画布保存、整链查询、版本管理和发布。
- 实验批次/订单创建、物料绑定和启动前自检。
- 调度计划生成、执行许可、首节点激活和后续节点推进。
- 基于 MQTT Outbox 的设备指令持久化投递。
- 设备 ACK、执行结果接收及任务状态推进。
- 任务暂停、恢复、取消和运行状态查询。
- Swagger / OpenAPI 3 文档及网关聚合能力。

因此，首期对接在技术上可行，不需要重新开发实验室调度引擎。

### 2.2 需要补齐的对接能力

现有接口主要服务内部管理页面，直接提供给第三方仍存在以下问题：

- 部分新增接口只返回成功或失败，不直接返回新记录 ID。
- 物料和订单缺少稳定的用户系统业务编码。
- 订单物料绑定依赖内部 JSON 结构，不适合要求用户系统直接拼装。
- 工艺保存与发布之间缺少统一、完整的对外服务端校验契约。
- 当前启动接口会记录自检结果，但不会仅因自检未通过而强制阻断。
- 尚未形成面向第三方系统的独立鉴权、错误码、幂等和回调规范。
- 尚未发现可靠的外部 HTTP 事件通知机制。

首期建设重点是增加稳定的对外适配层，而不是改造现有调度主链路。

## 3. 建设目标与验收结果

### 3.1 建设目标

形成以下业务闭环：

```text
用户系统添加物料
→ 查询组件并编排工艺
→ 校验并发布工艺
→ 创建实验订单并绑定物料
→ 启动前自检
→ 下发执行
→ 实验室设备执行并回传结果
→ 用户系统获取状态和实验结果
```

### 3.2 首期完成的判定标准

至少使用一条“单物料、单设备、单动作”的工艺完成以下验证：

1. 用户系统能够新增物料并取得实验室物料 ID。
2. 用户系统能够创建、保存、校验和发布工艺。
3. 用户系统能够使用外部订单号创建实验订单。
4. 自检通过后能够启动调度，设备能够收到正确指令。
5. 设备结果回传后，订单能够推进到正确终态。
6. 用户系统能够通过查询或回调获得完成、失败、取消等状态。
7. 重复创建订单或重复执行请求不会产生重复订单或重复设备指令。

## 4. 首期范围与边界

### 4.1 首期包含

- 设备状态、物料类、位置和组件库查询。
- 物料单个/批量新增及查询。
- 工艺创建、画布保存、校验、发布、详情和版本查询。
- 订单创建、详情、自检、执行、执行状态和结果查询。
- 订单暂停、恢复和取消。
- 订单状态异步回调及轮询补偿。
- 独立系统账号、固定租户映射、接口鉴权和审计。
- 创建与执行幂等、统一错误码、Swagger 对外文档分组。

### 4.2 首期不包含

- 用户系统自身的物料、工艺设计器和订单页面开发。
- 在黑灯实验室系统中开发第三方应用管理后台。
- 对外开放在线新增或修改组件类型、执行器和指令模板。
- 对外开放强制启动、失败步骤跳过、人工强制推进等高风险功能。
- 多外部系统、多租户动态映射和复杂订阅管理。
- 既有设备、位置、物料类及异常历史数据治理。

## 5. 系统职责划分

| 系统 | 主要职责 |
| --- | --- |
| 用户业务系统 | 维护外部物料编码、外部订单号；提供业务页面；调用实验室接口；接收并幂等处理事件回调 |
| 黑灯实验室对外适配层 | 参数校验、编码转换、幂等、权限控制、统一响应、内部接口编排和对外事件通知 |
| 黑灯实验室业务服务 | 物料、位置、工艺、订单、调度、结果和日志管理 |
| 设备网关及设备 | 接收 MQTT 指令，执行物理动作，上报 ACK、状态和执行结果 |

## 6. 总体对接架构

```text
┌──────────────────────┐
│     用户业务系统       │
│ 物料/工艺/订单/结果页面 │
└──────────┬───────────┘
           │ HTTPS / Blade Token
           ▼
┌──────────────────────┐
│  黑灯实验室统一网关     │
│ 鉴权、路由、审计、限流   │
└──────────┬───────────┘
           ▼
┌─────────────────────────────┐
│ /openapi/lab/v1 对外适配层    │
│ DTO转换/编码映射/幂等/自检门禁 │
└──────────┬──────────────────┘
           ▼
┌─────────────────────────────┐
│ 现有物料、工艺、订单、调度服务 │
└──────────┬──────────────────┘
           │ MQTT Outbox
           ▼
┌──────────────────────┐
│ 设备网关与实验室设备    │
└──────────────────────┘

任务状态变化：实验室系统 → 签名事件回调 → 用户业务系统
```

服务内规划路径为 `/openapi/lab/v1`；通过网关访问时，完整路径增加 `/blade-lab` 前缀，例如：

```text
POST /blade-lab/openapi/lab/v1/orders
```

## 7. 核心业务流程

### 7.1 物料登记流程

```text
查询物料类
→ 查询可用位置
→ 提交外部物料编码、物料类、位置和库存信息
→ 实验室校验物料类、位置和占用状态
→ 创建物料并返回 materialId
→ 用户系统保存 externalMaterialCode 与 materialId 的对应关系
```

业务规则：

- `externalMaterialCode` 在同一外部系统、同一租户内必须唯一。
- 新增物料必须指定有效物料类和存放位置。
- 位置被禁用、物料类型不匹配或容器位置被占用时不得创建。
- 新建物料默认处于可用、已入库、待命状态。
- 重复提交相同外部物料编码时返回原物料，不重复创建。

### 7.2 工艺编排与发布流程

```text
查询组件库
→ 创建工艺草稿
→ 保存完整画布
→ 服务端校验
→ 发布工艺
→ 返回工艺编码、工艺 ID 和版本号
```

服务端至少校验：

- 开始、结束节点是否完整。
- 节点和连线是否连通，是否存在孤立节点或非法循环。
- 组件类型及必填参数是否合法。
- 设备、设备类型和目标位置配置是否完整。
- 输入物料来源及来源明细是否完整。
- 节点步骤、执行器和指令模板引用是否有效。
- 汇集、并发、协同等规则是否满足现有调度要求。

发布必须复用同一套校验。校验未通过时不得生成可执行版本。

### 7.3 订单创建与执行流程

```text
选择已发布工艺及版本
→ 按工艺来源节点绑定具体物料
→ 创建订单并返回 orderId
→ 启动前自检
→ 自检通过后提交 execute
→ 生成调度计划并激活首节点
→ 设备指令经 Outbox 异步投递
→ 接收设备 ACK 和执行结果
→ 推进后续节点直至完成、失败或取消
```

业务规则：

- `externalOrderNo` 是用户系统订单的唯一标识，不得重复创建。
- 订单必须绑定已发布工艺，且工艺版本与创建时确认的版本一致。
- 所有工艺要求的输入物料来源明细都必须绑定具体物料。
- 同一物料不得重复绑定到多个冲突的来源配置。
- 参与启动的物料必须可用、已入库、处于待命状态并具有来源位置。
- 对外执行接口默认要求自检 `passed=true`，首期不开放强制启动。
- 执行接口返回受理成功不代表设备已经执行完成。
- `requestId` 是执行幂等键；重复请求返回原调度计划，不得重复生成设备指令。

### 7.4 状态与结果获取流程

用户系统可以同时使用两种方式：

1. **事件回调**：订单状态变化后，实验室系统主动推送事件。
2. **主动轮询**：用户系统定期查询执行状态；用于回调失败、网络中断或对账补偿。

订单进入完成、部分完成、失败或取消后，不再自动迁移到其他状态。实验结果、运行日志和数据文件通过独立查询接口获取。

## 10. 状态定义

### 10.1 对外订单状态

| 对外状态 | 含义 | 内部参考值 |
| --- | --- | --- |
| DRAFT | 草稿 | 0 |
| READY | 已就绪，可执行 | 10 |
| RUNNING | 正在执行 | 20 |
| PAUSED | 已暂停 | 30 |
| COMPLETED | 全部完成 | 50 |
| PARTIAL | 部分完成 | 55 |
| FAILED | 执行失败 | 60 |
| CANCELLED | 已取消 | 70 |

### 10.2 调度计划补充状态

调度计划还可能出现：

- `PREPARED`：已生成执行快照，尚未获得运行许可。
- `READY`：已具备启动条件。
- `FROZEN`：位置不确定或等待人工处置，禁止自动动作。

对外状态映射不得只依赖订单主状态；执行详情需要同时返回订单状态和计划状态，避免异常处置期间状态含义不完整。

### 10.3 设备在线状态

| 状态 | 含义 | 内部参考值 |
| --- | --- | --- |
| OFFLINE | 离线 | 0 |
| ONLINE | 在线 | 1 |

## 11. 自检与异常处理

启动前自检至少覆盖：

- 订单是否存在且属于当前授权租户。
- 工艺是否存在、已发布且版本一致。
- 工艺节点及板角色配置是否完整。
- 工艺所需设备是否配置并在线。
- 入料、出料或节点目标位置是否配置。
- 物料绑定是否完整，物料是否处于可启动状态。
- 数据服务、文件服务及位置占用是否满足执行要求。

自检响应应返回 `passed` 和逐项检查结果。用户系统应先展示未通过项并处理，再发起执行。

常见异常处理原则：

| 异常 | 处理原则 |
| --- | --- |
| 外部编码重复 | 幂等返回原记录，或返回明确冲突错误，不重复写入 |
| 工艺未发布或版本变化 | 阻止创建/启动，提示重新确认工艺版本 |
| 物料不可用或位置缺失 | 阻止启动，返回具体物料及原因 |
| 设备离线 | 默认阻止启动，不开放外部强制启动 |
| MQTT 投递失败 | 按现有 Outbox 机制重试，超过阈值后进入人工处置 |
| 设备执行失败 | 保存失败结果和日志，按现有状态机收敛并通知用户系统 |
| 回调失败 | 持久化事件并重试，用户系统通过轮询补偿 |

## 12. 安全、幂等与审计要求

### 12.1 鉴权与租户

- 首期为用户系统创建独立系统账号，复用现有 Blade Token 和网关鉴权。
- 系统账号固定映射到一个租户，外部请求不得自行指定或切换租户。
- 仅开放本方案约定的接口，不开放内部设备调试、强制推进和组件管理接口。
- 生产环境使用 HTTPS，凭证不得写入文档、日志或前端代码。

### 12.2 幂等要求

| 操作 | 幂等标识 | 要求 |
| --- | --- | --- |
| 新增物料 | `externalMaterialCode` | 重复请求不生成重复物料 |
| 创建工艺 | 外部工艺编码 | 重复请求不生成无关联的重复工艺 |
| 创建订单 | `externalOrderNo` | 重复请求返回原订单 |
| 执行订单 | `requestId` | 重复请求返回原计划，不重复派发 |
| 事件接收 | `eventId` | 用户系统重复事件只处理一次 |

### 12.3 数据与审计

- 所有长整型 ID 使用字符串传输，避免雪花 ID 精度丢失。
- 时间使用带时区的 ISO 8601 格式。
- 记录外部系统、请求 ID、业务单号、操作类型、处理结果和失败原因。
- 日志不得记录 Token、回调密钥等敏感信息。

## 13. 事件回调方案

### 13.1 通知事件

首期至少支持：

- `ORDER_STARTED`
- `ORDER_PAUSED`
- `ORDER_RESUMED`
- `ORDER_COMPLETED`
- `ORDER_PARTIAL`
- `ORDER_FAILED`
- `ORDER_CANCELLED`

### 13.2 回调报文示例

```json
{
  "eventId": "EVT-20261117-000001",
  "eventType": "ORDER_COMPLETED",
  "externalOrderNo": "EXP-20261117-001",
  "orderId": "实验室订单ID",
  "planId": "调度计划ID",
  "status": "COMPLETED",
  "occurredAt": "2026-11-17T10:30:00+08:00",
  "errorCode": null,
  "errorMessage": null
}
```

### 13.3 可靠性要求

- 回调事件先持久化，再异步发送。
- 请求包含 HMAC 签名、时间戳和事件 ID。
- 用户系统验证签名并按 `eventId` 幂等接收。
- 回调超时或非成功响应按策略重试。
- 服务重启后能够恢复未成功事件。
- 回调乱序时，用户系统应结合事件时间和主动查询确认最新状态。
- 首期回调地址及密钥通过配置维护，不开发订阅管理页面。

## 14. 统一响应与错误码

统一响应结构：

```json
{
  "code": "SUCCESS",
  "message": "处理成功",
  "data": {},
  "requestId": "REQ-20261117-001"
}
```

建议错误码分类：

| 错误码 | 含义 |
| --- | --- |
| MATERIAL_NOT_FOUND | 物料不存在 |
| MATERIAL_CODE_CONFLICT | 外部物料编码冲突 |
| MATERIAL_NOT_AVAILABLE | 物料不可用于启动 |
| LOCATION_NOT_FOUND | 位置不存在 |
| LOCATION_OCCUPIED | 位置已占用 |
| WORKFLOW_NOT_FOUND | 工艺不存在 |
| WORKFLOW_INVALID | 工艺校验失败 |
| WORKFLOW_NOT_PUBLISHED | 工艺未发布 |
| WORKFLOW_VERSION_CHANGED | 工艺版本已变化 |
| ORDER_NOT_FOUND | 订单不存在 |
| ORDER_NO_CONFLICT | 外部订单号冲突 |
| ORDER_STATE_INVALID | 当前订单状态不允许该操作 |
| SELF_CHECK_FAILED | 启动自检未通过 |
| DEVICE_OFFLINE | 所需设备离线 |
| EXECUTE_REQUEST_CONFLICT | 执行幂等键已用于其他请求 |
| EXECUTION_FAILED | 任务执行失败 |
| CALLBACK_DELIVERY_FAILED | 回调投递失败 |

业务错误应返回明确、可处理的错误码，不向用户系统暴露 SQL、堆栈和内部约束名称。

## 15. 数据改造与内部复用原则

### 15.1 数据改造

- 物料增加外部物料编码，并建立租户范围内的唯一约束。
- 订单增加外部订单号，并建立租户范围内的唯一约束。
- 工艺使用稳定的外部工艺编码作为防重和版本归组依据。
- 新增外部回调事件持久化记录，用于投递状态、重试次数、下次重试时间和错误追踪。
- 不改变现有订单、计划和设备步骤状态机。

### 15.2 内部复用

- 复用现有设备运行时状态查询。
- 复用现有物料新增、默认状态、位置校验和占用处理。
- 复用现有工艺画布保存、整链详情和发布能力。
- 复用现有订单物料绑定编译器、调度计划准备和启动能力。
- 复用现有 MQTT Outbox、设备 ACK/结果回调及任务推进能力。
- 复用现有暂停、恢复、取消和状态查询能力。

对外适配层只负责契约转换和业务编排，不另建一套平行状态机。

## 16. 实施阶段与工作量估算

| 阶段 | 主要工作 | 产出 |
| --- | --- | --- |
| 1. 契约评审 | 确认字段、画布 schema、状态、错误码、回调和鉴权 | 双方确认的接口契约 |
| 2. 基础与物料 | 编码映射、基础查询、新增返回 ID、幂等 | 可登记并查询物料 |
| 3. 工艺适配 | 工艺创建、画布保存、服务端校验和发布 | 可发布外部编排工艺 |
| 4. 订单执行 | 订单创建、绑定转换、自检门禁、执行和查询 | 可下发并跟踪实验订单 |
| 5. 回调与验收 | 持久化回调、Swagger 分组、模拟器和设备联调 | 完整闭环验收 |

在现有调度链路稳定、仅对接一个用户系统且不开发外部管理后台的前提下：

- 后端开发粗略估算：15–20 人日。
- 联调与验收粗略估算：5–8 人日。
- 不包含用户系统自身开发和既有基础数据治理。

工艺画布契约复杂度和现场设备联调是主要工作量波动因素，正式排期应在接口契约评审后确认。

## 17. 验收方案

### 17.1 文档与安全验收

- Swagger 外部分组只包含约定接口。
- 请求模型、必填字段、响应、错误码和鉴权说明完整。
- 无凭证、无效凭证及跨租户访问均被拒绝。
- 内部调试和高风险接口未出现在外部分组。

### 17.2 物料验收

- 新增物料成功并返回 ID。
- 重复外部编码不生成重复物料。
- 非法物料类、禁用位置和占用位置返回明确错误。
- 物料状态、位置和库存满足订单启动要求。

### 17.3 工艺验收

- 能够通过外部画布数据创建、保存、校验和发布工艺。
- 非法图、缺失设备、缺失物料来源等场景不能发布。
- 已发布工艺能够按指定版本创建订单。

### 17.4 订单执行验收

- 外部订单号创建成功，内部物料绑定快照正确。
- 重复创建返回原订单。
- 自检未通过时默认不能执行。
- 自检通过后启动，MQTT 收到正确设备指令。
- 设备 ACK 和执行结果回传后，流程正确推进。
- 重复执行 `requestId` 不重复生成设备 Outbox。
- 暂停、恢复、取消和异常状态映射正确。

### 17.5 回调与结果验收

- 完成、失败和取消事件能够送达用户系统。
- 重复事件能够被幂等处理。
- 回调失败能够重试，服务重启后能够恢复。
- 用户系统能够查询实验结果、日志和数据文件信息。

## 18. 主要风险与控制措施

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 工艺画布契约复杂 | 双方字段理解不一致、返工 | 先冻结组件和画布 schema，以单节点工艺打样 |
| 直接开放内部接口 | 参数复杂、权限风险、后续不兼容 | 使用独立 OpenAPI 适配层 |
| 重复创建或重复执行 | 重复订单、重复物理动作 | 外部单号唯一约束、执行幂等和原计划返回 |
| 自检失败仍启动 | 设备异常或物料位置不一致 | 对外默认强制自检门禁，不开放强制启动 |
| 设备或 MQTT 环境不稳定 | 任务等待、失败或超时 | 复用 Outbox、超时和恢复机制，先模拟器后真实设备 |
| 回调丢失或乱序 | 用户系统状态不一致 | 持久化重试、事件幂等、轮询对账 |
| 外部系统越权访问 | 数据泄露或误操作 | 独立账号、固定租户、最小接口权限和审计 |

## 19. 双方待确认事项

正式开发前需要双方确认：

1. 用户系统的外部物料编码、工艺编码和订单号规则。
2. 工艺设计器使用的画布 JSON 结构及组件参数 schema。
3. 用户系统负责人账号与实验室操作人的映射方式。
4. 订单状态、失败原因和实验结果的字段范围。
5. 回调地址、签名算法、重试策略及接收 SLA。
6. 网关访问地址、网络策略、证书和系统账号配置。
7. 首条验收工艺、设备、物料类、位置和模拟器/真实设备范围。

上述事项确认后，即可将本方案拆分为详细接口契约和开发任务。
