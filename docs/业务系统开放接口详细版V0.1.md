## 1. 协议边界与业务对象

### 1.1 支持的业务闭环

```text
获取应用令牌
  → 查询设备、位置、负责人和主数据
  → 创建物料类型/物料类（有权且未预置时）
  → 创建物料并确认实物就位
  → 获取组件库、设备组件能力和参数 Schema
  → 新建工艺、保存节点与连线、校验、发布
  → 获取该发布版本的订单输入 Schema
  → 创建订单并绑定具体物料
  → 自检、启动、查询或控制
  → 获取结果、文件、状态通知并对账
```

客户通过自己的后端调用本协议。客户前端不保管应用密钥；其画布、节点展示和表单交互由客户自行开发。嵌入我方设计器是独立交付选项，不在本版定义嵌入授权和浏览器消息协议。

### 1.2 责任边界

- 客户系统负责业务编号、工艺设计输入、订单发起和业务结果展示。
- 实验室平台负责资源权限、工艺语义校验、执行计划、设备调度、回执和物理状态。
- 设备、驱动、位置拓扑及安全联锁由我方预配置；客户不能通过本协议新增驱动或发送原始 MQTT 指令。
- 物料登记不代表实物已经进入设备。就位确认必须来源于授权人员或可信装载流程。
- 工艺描述物料类别和输入要求；订单绑定具体物料；计划在启动时固化执行快照。
- 本版不开放执行状态直接写入、任意脚本、强制跳过、设备动作盲重试、运行中物料位置修正。

### 1.3 标识与版本

| 标识 | 含义与规则 |
| --- | --- |
| `materialId` | 平台具体物料 ID，字符串 |
| `externalMaterialCode` | 客户具体物料唯一编号，不等于条码 `serialNo` |
| `workflowId` | 平台某个工艺草稿/版本记录 ID；派生新版本获得新 ID |
| `workflowCode` | 平台工艺系列编码；同系列多个版本共享 |
| `externalWorkflowCode` | 客户工艺系列编号；同系列多个版本共享 |
| `workflowVersion` | 平台分配的正整数版本号，创建版本时占号，可不连续 |
| `revision` | 可编辑资源的并发修订号，正整数；不是发布版本 |
| `nodeKey/edgeKey/inputKey` | 客户生成、工艺定义内稳定的节点/连线/物料输入键 |
| `orderId/orderNo` | 平台订单 ID 和可读订单号 |
| `externalOrderNo` | 客户唯一订单号，同一订单重试保持不变 |
| `planId` | 执行计划 ID；创建订单时为空 |
| `operationId` | 一次异步启动/控制操作 ID，不是实验结果 ID |
| `stateVersion` | 订单公共状态、操作状态与结果摘要的单调递增版本，十进制整数字符串 |

外部编号按“租户＋接入应用＋资源类型＋外部编号”唯一。工艺系列内部按版本区分记录，不能给同系列每个版本重新分配外部系列编号。外部编号不可修改，归档或删除后不自动释放。

物料类 `categoryId` 标识一组固定规格；本版规格作为物料类字段提供，不单独建设 `/material-specifications`。更改影响夹取、尺寸、容量的规格须创建新的物料类，不能改变已引用物料的物理语义。

### 1.4 示例与真实能力

本文示例使用 `material_input`、`device_action`、`end`、`flow`、`heat` 等说明性编码。真实可用编码、端口、约束、参数以及是否支持条件/循环/移液，必须来自组件库查询，不能从示例推定环境支持。

工艺在目标环境通过发布校验才具备执行资格；即使接口传输格式合法，也不等于具备执行资格。

## 2. 通用通信规范

### 2.1 地址、格式与请求头

| 项目 | 约定 |
| --- | --- |
| 示例服务地址 | `https://lab-api.example.com`，为说明域名，不是真实服务 |
| 业务前缀 | `/openapi/v1` |
| 认证入口 | `/oauth/token`，不带业务前缀 |
| 传输 | HTTPS，TLS 1.2 或以上 |
| 请求体 | UTF-8 JSON，`Content-Type: application/json`；认证例外 |
| 响应体 | UTF-8 JSON；令牌、304 和文件流例外 |
| 业务授权 | `Authorization: Bearer {access_token}` |
| 客户请求标识 | 可选 `X-Client-Request-Id`，1～64 个字母、数字、`_`、`-` |
| 服务端请求标识 | 响应头 `X-Request-Id` 与响应体 `requestId` 一致 |
| 幂等 | 有副作用的 POST/PUT/PATCH 必须带 `Idempotency-Key` |
| 并发控制 | 指定接口带 `If-Match: "rev-{revision}"`；版本不匹配返回 412 |

本协议不要求客户端发送内部 `Blade-Auth` 或后台 Basic 客户端头。机器身份到现有框架身份的转换由服务端完成。不得在请求体或请求头自行指定租户来切换权限。

### 2.2 字段规则

- 标记 `R` 为必填，`O` 为可选，`RO` 为只读；请求中出现只读字段或未知字段返回 400。
- ID 为 1～64 字符不透明字符串，不解析为数字，不假定雪花算法。
- 外部编号为 1～128 字符，区分大小写，禁止首尾空白及控制字符；不能依赖服务端自动 trim。
- 稳定业务键采用 `[A-Za-z][A-Za-z0-9_-]{0,63}`。节点、边、输入分别在自己的键空间内唯一。
- 名称 1～128 字符；描述和备注最多 2000 字符；控制原因最多 500 字符。
- 时间采用 RFC 3339，服务端输出 UTC，例如 `2026-11-17T08:00:00Z`；查询起始时间包含，结束时间不包含。
- `revision`、版本号、分页大小、计数采用 JSON 整数，范围不超过 2147483647；序号和字节长度用十进制整数字符串。
- 布尔值为 JSON `true/false`，不使用 0/1。参数值按参数 Schema 传输，不用 JSON 字符串套 JSON。
- 固定物理尺寸等精确十进制值用非指数十进制字符串，最多 12 位整数和 6 位小数；动态实验参数类型由 Schema 明确。
- 请求缺失字段按接口默认值处理；只有明确声明可空的字段才允许 `null`。
- 客户可忽略响应中未来新增的可选字段；不能忽略未知状态并继续自动操作，应显示未知状态并停止自动控制。

### 2.3 统一响应

成功结构：

```json
{
  "code": "SUCCESS",
  "message": "处理成功",
  "requestId": "req_20261117_0001",
  "data": {
    "materialId": "210000000000000001",
    "externalMaterialCode": "MAT-20261117-001"
  }
}
```

失败结构：

```json
{
  "code": "VALIDATION_FAILED",
  "message": "工艺参数校验未通过",
  "requestId": "req_20261117_0002",
  "data": null,
  "errors": [
    {
      "code": "PARAMETER_REQUIRED",
      "path": "/nodes/1/actions/0/parameters/temperature",
      "nodeKey": "n_heat",
      "edgeKey": null,
      "inputKey": null,
      "message": "缺少目标温度"
    }
  ]
}
```

`errors` 仅错误响应可选；元素包含必填 `code/path/message`，可选且可空的节点、连线、输入键。`path` 为请求体 JSON Pointer；不对应请求字段的系统错误可用空字符串。客户端按 `code` 判断，不解析中文 `message`。

业务失败使用实际 HTTP 错误状态，不将所有异常包装成 HTTP 200。响应不包含堆栈、SQL、凭据或未授权资源信息。

### 2.4 分页、筛选与缓存

普通列表统一参数：`page` 默认 1；`pageSize` 默认 20，范围 1～100；`updatedFrom/updatedTo` 可选。额外筛选字段由接口表列出；未知筛选字段返回 400。

统一返回 `data={items: T[], page: integer, pageSize: integer, total: integer}`。默认按 `createdAt` 升序、ID 升序排序；没有 `createdAt` 的静态目录按 `sort`、编码升序。执行日志、步骤、结果按各节定义排序。

页码列表不保证跨页读取时的全局快照，不应用它替代事件游标进行无遗漏增量同步。精确外部编号查询必须使用专用筛选字段，不使用模糊名称搜索。

目录响应可带 `ETag`，客户端通过 `If-None-Match` 获得 304（无响应体）。缓存必须按应用身份和权限隔离；保存和发布仍在服务端重新检查引用权限。

### 2.5 幂等与并发

幂等键为 8～96 个字母、数字、`_`、`-`。作用域为租户、应用、HTTP 方法、规范化路径和幂等键。

1. 服务端先检查当前认证与授权，再按键查重，随后才执行资源修订号检查。
2. 相同键、相同请求体和相同 `If-Match` 重放原 HTTP 状态与业务结果；`requestId` 为本次新值，返回 `Idempotency-Replayed: true`。
3. 请求摘要包括规范化 JSON、语义查询参数和 `If-Match`，不包括访问令牌及请求追踪头。对象键排序，数组顺序保留，不将字符串与数字视为相同。
4. 相同键不同摘要返回 `409 IDEMPOTENCY_CONFLICT`；同键请求仍处理中返回 `409 REQUEST_IN_PROGRESS` 和 `Retry-After`。
5. 并发查重使用数据库唯一约束。事务提交与幂等结果持久化必须一致；不能产生资源成功、幂等记录丢失的窗口。
6. 同键完整结果至少保留 7 天。外部编号唯一性和每订单唯一启动计划不随此窗口失效。
7. 超过窗口后再次使用同键可能作为新请求处理；客户不得据此重做物理操作，应先查询资源或操作结果。
8. 无副作用的 `/validate` 和 `/precheck` 不要求幂等键，每次重新检查。

`If-Match` 使用最近一次资源读取或创建/修改成功响应返回的 ETag；发生延迟、冲突或异步变化后先重新 GET。缺失返回 428，失配返回 412；不得使用 `*`。物料、工艺、订单的创建、详情、修改以及就位确认/工艺发布响应必须返回该主体的 `revision` 和 ETag；列表中的 revision 只作参考。修订号保护业务编辑和运行状态竞争，订单 `stateVersion` 独立用于事件排序，不可代替 ETag。

PATCH 使用 `application/json` 的字段更新语义：缺失不变，出现则替换；数组整体替换。仅描述、备注允许 `null` 清空；至少提供一个允许修改的字段。它不是 JSON Patch。

### 2.6 初始限制

以下为本协议的初始配置基线，不是性能实测承诺。生产值在接入登记单中签字确认，变更需提前告知。

| 项目 | 初始值 |
| --- | --- |
| 普通 JSON 请求体 | 最大 2 MiB |
| 工艺定义请求体 | 最大 5 MiB，200 节点、400 连线、200 物料输入 |
| 批量物料 | 每批 1～100 项 |
| 单订单绑定实物数 | 最大 1000，且不超过工艺声明数量 |
| JSON 嵌套深度 | 最大 16 层 |
| 读请求速率 | 每应用持续 20 次/秒，突发桶容量 40 |
| 写请求速率 | 每应用持续 5 次/秒，突发桶容量 10 |
| 校验/发布/自检并发 | 每应用最多 2 个 |
| 事件留存 | 至少 30 天 |
| 短期幂等结果留存 | 至少 7 天 |
| 控制操作记录 | 订单存续期间保留；订单归档后至少 30 天 |

超限返回 413 或 429。429 带 `Retry-After`（整数秒）；业务代码区分请求大小和速率超限。客户端建议连接超时 5 秒、读取超时 30 秒；HTTP 超时不代表执行取消。

## 3. 认证与权限

### 3.1 获取令牌

`POST /oauth/token`

请求类型 `application/x-www-form-urlencoded`，通过 HTTP Basic 提交专用 `client_id:client_secret`，参数：

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `grant_type` | R | 固定 `client_credentials` |
| `scope` | O | 空格分隔的权限集合；缺失使用该应用默认授权，不得超出注册权限 |

```http
POST /oauth/token HTTP/1.1
Host: lab-api.example.com
Authorization: Basic {base64(client_id:client_secret)}
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials&scope=resource.read%20material.read%20material.write
```

HTTP 200；认证响应不使用业务 envelope：

```json
{
  "access_token": "EXAMPLE_TOKEN_NOT_VALID",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "resource.read material.read material.write"
}
```

令牌响应带 `Cache-Control: no-store`。不发放刷新令牌；客户在到期前 60 秒重新获取，并对并发换令牌做单飞控制。实际有效期以 `expires_in` 为准。

错误响应为 `{"error":"invalid_client","error_description":"客户端认证失败"}`；Basic 认证失败使用 401 和 `WWW-Authenticate: Basic`，不支持授权方式/非法 scope 使用 400，分别为 `unsupported_grant_type`、`invalid_scope`；缺参数为 `invalid_request`。

业务请求令牌失效返回 401、`WWW-Authenticate: Bearer` 和 `UNAUTHORIZED`。最多自动换令牌重试一次，写操作保留原幂等键。

### 3.2 权限范围

| scope | 可调用业务 |
| --- | --- |
| `resource.read` | 设备、位置、位置组、负责人查询 |
| `masterdata.read` | 物料类型、物料类、变量库查询 |
| `masterdata.write` | 受控创建物料类型与物料类 |
| `material.read` | 物料列表和详情 |
| `material.write` | 物料登记和基础信息修改 |
| `material.place` | 物理就位确认 |
| `workflow.read` | 工艺查询、组件目录、版本和输入 Schema |
| `workflow.write` | 工艺创建、编辑、派生版本和校验 |
| `workflow.publish` | 发布工艺 |
| `order.read` | 订单、步骤、日志、异常和操作状态 |
| `order.write` | 创建和修改订单、自检 |
| `order.execute` | 启动 |
| `order.control` | 暂停、恢复、取消 |
| `result.read` | 实验结果、文件和下载 |
| `event.read` | 外部事件补拉 |

每个 scope 只允许其登记范围内的对象；拥有 scope 不代表可访问所有租户数据。无接口权限返回 403；对象不存在或不可见统一返回 404，避免枚举。

负责人来自已授权 `/operators` 映射。应用身份不是实验负责人，不能直接提交任意用户 ID。共享主数据、工艺或设备需显式授权，只读共享不包含修改权。

### 3.3 接入登记

上线前登记环境地址、应用 ID、租户、scope、负责人映射、共享资源、回调域名、回调密钥 ID、限流值、数据保留期和联络人。生产与测试应用、凭据、数据完全隔离。应用密钥轮换和停用由我方受控管理，本文不开放开发者管理 API。

## 5. 资源与主数据

### 5.1 设备、位置和负责人

各列表使用通用分页，以下列出额外筛选条件及 `items` 元素。除标注可空外，响应字段均返回；没有值的可空字段返回 null，集合返回空数组。

| 接口 | 额外查询参数 | 元素字段 |
| --- | --- | --- |
| `/devices` | `deviceTypeCode`、`nodeTypeCode`、`online` 布尔、`code` 精确编码 | `deviceId`、`code`、`name`、`deviceTypeCode`、`online`、`enabled`、`workState`、`capabilityVersion`、`createdAt`、`updatedAt` |
| `/locations` | `deviceId`、`categoryId`、`available` 布尔、`code` | `locationId`、`code`、`name`、`deviceId` 可空、`enabled`、`available`、`slotMode`、`rows`、`columns`、`supportedCategoryIds`、`occupiedSlots`、`createdAt`、`updatedAt` |
| `/location-groups` | `deviceId`、`code` | `groupId`、`code`、`name`、`deviceId`、`locationIds`、`enabled`、`createdAt`、`updatedAt` |

位置 `slotMode=SINGLE/GRID`；SINGLE 的 rows/columns 均为 1；GRID 为正整数，槽位编码固定从 1 开始的 `"行-列"`。`occupiedSlots` 仅含槽位编码，不泄漏其他应用物料 ID；最多 1000 槽，超出规模需另议分片能力。`available` 是状态提示，不构成预留。

`supportedCategoryIds` 为空表示没有可用的已授权匹配类，不表示支持任意规格。负责人查询返回已建立映射的人员，不返回密码、手机等无关个人数据。

### 5.4 变量库

`GET /variables`：额外筛选 `code`、`valueType`、`enabled`，只返回允许引用的库变量，不返回其他订单运行值。

## 6. 物料登记、维护和就位

### 6.1 单个登记

`POST /materials`。请求：

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `externalMaterialCode` | string | R，不可变 |
| `name` | string | R |
| `categoryId` | ID | R，存在且有权使用 |
| `ownerOperatorId` | ID | R，授权归属人 |
| `serialNo` | string | O，最多 128，默认空；不代替外部编号 |
| `stockQuantity` | integer | O，默认 1，范围 1～1000000 |
| `description`、`remark` | string | O，默认空 |

创建仅登记业务对象，不接受 `locationId/stored/status/available`。返回完整 Material。

Material = 请求字段，加 `materialId`、`status`、`available`、`placement`、`revision`、`createdAt`、`updatedAt`。`placement` 未就位为 null；已就位时为 `{locationId,containerPosition,postureDegrees,confirmedAt}`。

`status=IDLE/IN_TRANSIT/EXECUTING/EXCEPTION/COMPLETED`。新建为 IDLE，但 available=false、placement=null；available 由状态、就位、规格和锁定综合计算，客户端不可直接写入。

```json
{
  "externalMaterialCode": "MAT-20261117-001",
  "name": "实验孔板001",
  "categoryId": "210000000000000102",
  "ownerOperatorId": "210000000000000103",
  "serialNo": "BARCODE-001",
  "stockQuantity": 1,
  "remark": "首轮联调"
}
```

### 6.2 批量登记

`POST /materials/batch`，请求 `{materials: MaterialCreate[]}`，1～100 项。

批内外部编号重复或外层结构非法时整批 400，不创建任何项。通过外层检查后逐项验证、逐项事务，允许部分成功；项错误不回滚其他项。禁止将批量作为一次外部设备操作。

HTTP 200 的 `data` 为：

```json
{
  "total": 2,
  "succeeded": 1,
  "failed": 1,
  "items": [
    {
      "index": 0,
      "externalMaterialCode": "MAT-20261117-001",
      "success": true,
      "code": "SUCCESS",
      "message": "创建成功",
      "materialId": "210000000000000001"
    },
    {
      "index": 1,
      "externalMaterialCode": "MAT-20261117-002",
      "success": false,
      "code": "RESOURCE_NOT_FOUND",
      "message": "物料类不存在或无权访问",
      "materialId": null
    }
  ]
}
```

同一批幂等键重试恢复原批次进度和最终结果，不能把已成功项重新创建。只修正失败项时，提交仅含失败项的新批次和新幂等键。平台须持久化每项状态；进程中断不能丢失成功项与批次的关联。

### 6.3 查询与修改

`GET /materials` 额外筛选 `externalMaterialCode`、`categoryId`、`status`、`available`、`locationId`。返回 Material 分页。`GET /materials/{id}` 返回 Material 和 ETag。

PATCH 仅允许 `name/serialNo/description/remark`；仅 IDLE 且未锁定物料可修改。不得修改 categoryId、库存、位置、状态、归属和外部编号；需要纠正物理数据时走受控现场流程。

### 6.4 就位确认

`POST /materials/{id}/placement-confirmations`，必须 I、E。请求：

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `locationId` | ID | R |
| `containerPosition` | string | R，格式 `"1-1"`；SINGLE 固定 `"1-1"` |
| `postureDegrees` | decimal string | O，默认 `"0"`，范围 [0,360) |
| `confirmedByOperatorId` | ID | R，必须具有确认资格且在应用映射内 |
| `observedAt` | timestamp | R，实物确认时间；距接收时间不超过 5 分钟，未来容差 60 秒 |
| `remark` | string | O |

服务端同时验证物料 IDLE、未被占用、位置兼容、槽位空闲和确认权限。并发确认同一槽位时最多一个成功，另一个 409 `LOCATION_OCCUPIED`。时钟/确认过期为 422 `PLACEMENT_CONFIRMATION_EXPIRED`。

返回 `{confirmationId, material: Material}`，并返回物料新的 ETag。仅初次就位允许此入口；相同幂等请求重放；已就位的新确认返回 `PLACEMENT_ALREADY_CONFIRMED`，不能借此搬运物料。装载自动化系统使用登记的可信确认人映射，不能伪造人工确认。

## 7. 组件库与动态表单协议

### 7.1 获取完整组件目录

`GET /workflow-capabilities?catalogVersion={version}`。catalogVersion 可选；缺失返回应用当前可用目录，指定时读取对应定义快照。节点、端口、参数及规则定义不可变，enabled/designable/publishable 仍按当前授权和禁用策略计算；ETag 必须同时反映定义版本和这些有效性状态。响应不分页，单目录最多 200 个节点类型、400 个连线类型、5 MiB，超过时需升级协议或划分授权目录，不能静默截断。

`data`：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `schemaVersion` | string | 本版 `"1.0"` |
| `catalogVersion` | string | 目录快照版本，1～64 字符不透明值 |
| `generatedAt` | timestamp | 快照生成时间 |
| `nodeCategories` | CategoryItem[] | `{code,name,iconKey,color,sort}` |
| `nodeTypes` | NodeType[] | 节点定义，见下文 |
| `edgeTypes` | EdgeType[] | 连线定义，见下文 |
| `rules` | Rule[] | 可公开的约束描述 |

图标 `iconKey` 是名称而不是可执行代码/HTML；客户不认识时使用通用图标。`color` 为 `#RRGGBB`，sort 为非负整数。

NodeType 字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `typeCode/name/categoryCode/description` | string | 稳定类型编码、名称、分类及说明 |
| `iconKey/color/sort` | string/string/integer | 展示信息 |
| `enabled/designable/publishable` | boolean | 当前授权下能否使用、编辑和发布 |
| `canBeStart/canBeEnd` | boolean | 能否作为起点或终点 |
| `ports` | Port[] | `{portKey,direction,side}`；direction=IN/OUT，side=TOP/RIGHT/BOTTOM/LEFT |
| `maxIncoming/maxOutgoing` | integer/null | null 为不限，0 为禁止 |
| `allowedDeviceTypeCodes` | string[] | 允许的设备类型；空表示不允许选设备 |
| `requiresDevice/allowMaterials` | boolean | 是否必须绑定设备、是否允许物料关联 |
| `minActions/maxActions` | integer | 节点设备能力引用数量限制，0 表示不需动作 |
| `parameterSchema` | JSON Schema object | 节点参数定义，见 7.2 |
| `editor` | object | `{mode,rendererKey,rendererVersion,uiSchema}` |

`editor.mode=SCHEMA/CUSTOM`；SCHEMA 的 rendererKey/rendererVersion 为 null，uiSchema 可空；CUSTOM 必须返回稳定 rendererKey/version 及有效 parameterSchema。客户必须实现对应编辑器，或将该类型标记为不可编辑。

**内部 `formContent=CODE` 不得直接作为对外表单定义。** 未转换为完整参数 Schema 的节点必须 designable=false、publishable=false，并在 rules 中说明原因。不能将空 Schema 当作“任意参数都合法”。

EdgeType：

`{typeCode,name,description,sort,kind,allowedSourceTypeCodes,allowedTargetTypeCodes,parameterSchema}`。kind 为 `FLOW/CONDITION/JOIN/TRANSFER/INTERVAL/LOOP`；具体语义、参数和适配规则由对应目录确定。两端允许类型列表非空；未列出的连接不能提交。

Rule：

`{ruleCode,severity,targetTypeCodes,message,validationMode}`。severity=ERROR/WARNING；validationMode=SERVER/SCHEMA。客户端不执行服务器下发的 JavaScript 或表达式字符串。SERVER 规则通过 `/validate` 获取结果；SCHEMA 规则由节点/连线 Schema 表达。

旧目录可查询不意味着它仍有发布资格；组件禁用、权限撤销或安全变更可使旧工艺不能再启动。服务器必须明确报错，不静默替换目录版本或动作。

### 7.2 参数 Schema 与 UI Schema

采用 JSON Schema Draft 2020-12 的受限子集：

- 支持 `type/title/description/properties/required/additionalProperties/enum/const/default/minimum/maximum/exclusiveMinimum/exclusiveMaximum/multipleOf/minLength/maxLength/pattern/items/minItems/maxItems/uniqueItems/oneOf`，可含固定的 Draft 2020-12 `$schema` 声明。
- 参数根必须是 object，并设 `additionalProperties=false`。支持类型为 object、array、string、integer、number、boolean；可空参数用 oneOf 显式声明含 null。
- 不接受远程 `$ref`、可执行脚本、动态代码；本版也不发出本地 `$ref`，保持目录自包含。
- `default` 是提示；客户端显式提交选用值，服务器不能凭未固化的新版默认值改变已发布工艺。
- `uiSchema.fields` 数组元素为 `{path,widget,order,unit,optionSource}`。path 为相对参数对象的 JSON Pointer；widget=TEXT/NUMBER/SELECT/SWITCH/OBJECT/ARRAY/CUSTOM；unit 和 optionSource 可空。
- optionSource 仅允许 `{resource,filters,valueField,labelField}`。resource 限 `material-categories/variables/locations/location-groups`；filters 是该资源允许的固定查询值，不是任意 URL。valueField/labelField 必须是对应资源公开字段。
- 参数单位必须通过 uiSchema.fields[].unit 明确；不得在界面显示摄氏度、提交时却按开尔文解释。

示例 Schema：

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "additionalProperties": false,
  "properties": {
    "temperature": {
      "type": "number",
      "title": "目标温度",
      "minimum": 20,
      "maximum": 80
    },
    "durationSeconds": {
      "type": "integer",
      "title": "持续时间",
      "minimum": 1,
      "maximum": 3600
    }
  },
  "required": ["temperature", "durationSeconds"]
}
```

### 7.3 获取设备组件能力

`GET /devices/{id}/capabilities?capabilityVersion={version}`。版本可选；缺失返回当前版本。返回：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `deviceId` | ID | 设备 |
| `capabilityVersion` | string | 不可变能力快照版本 |
| `components` | Component[] | 允许编排的组件能力，不包含任意调试能力 |

Component：

`{componentCode,name,description,enabled,parameterSchema,outputSchema,uiSchema,materialPolicy,executionPolicy}`。

- parameterSchema 为实际可提交参数的受限 JSON Schema。
- outputSchema 描述动作可公开的结果字段；没有结果时是封闭空对象 Schema。
- materialPolicy=`NONE/OPTIONAL/REQUIRED`，决定动作所在节点是否必须关联物料。
- executionPolicy=`{timeoutSeconds,supportsSafePause,supportsSafeCancel,retryMode}`；timeoutSeconds 为正整数，retryMode=`NONE/PLATFORM_CONTROLLED`。这些均为只读说明，不允许客户覆盖驱动安全策略。
- 不返回内部模板 ID、模板正文、通信地址、MQTT topic、驱动密钥。

能力参数及执行策略按 capabilityVersion 固定，enabled 按当前授权及安全策略计算。旧能力被撤销后必须拒绝新发布/启动，不能因为请求指定旧版本而继续允许动作。

当前内部 `functionList` 的 `type=1` 可作为组件来源，但对外必须增加授权过滤和参数规范化，不能把所有能力原样暴露。

### 7.4 客户设计器加载步骤

1. 获取完整目录，按 nodeCategories/nodeTypes 绘制左侧组件库。
2. 根据 editor.mode 选择通用表单或已实现的专用编辑器。
3. 拖入节点时生成 nodeKey，不使用数据库主键充当节点键。
4. 查询适配设备，选择后获取能力快照及位置/位置组。
5. 选择组件能力并按 parameterSchema 填写参数，保存 capabilityVersion。
6. 引用物料输入与运行参数；填写连线参数及布局。
7. 保存定义，服务端校验，发布并取得固定版本。

切换设备必须重新选择兼容组件并校验参数，不能沿用另一设备的能力快照。组件目录变更后，已打开草稿不自动替换其 catalogVersion，由用户显式迁移并重新校验。

## 8. 工艺定义数据协议

### 8.1 顶层 WorkflowDefinition

`PUT /workflows/{id}/definition` 直接提交下表对象，不包装成内部 flowData 字符串或 React Flow 对象。

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `schemaVersion` | string | R，固定 `"1.0"` |
| `catalogVersion` | string | R，来自组件目录 |
| `nodes` | Node[] | R，草稿可为空，发布必须非空 |
| `edges` | Edge[] | R，可为空，由图规则决定能否发布 |
| `materialInputs` | MaterialInput[] | R，无实物工艺可为空 |
| `parameterDefinitions` | ParameterDefinition[] | R，无运行参数时为空 |
| `parameterBindings` | ParameterBinding[] | R，无动态赋值时为空 |
| `layout` | object | O，缺失采用默认布局；见 8.7 |

定义中不包含 workflowId/version/revision，它们由路径、响应和 ETag 管理。服务端保存完整替换后的定义，未提交的旧节点和连线视为删除，但必须保留发布版本的历史内容。

### 8.2 节点 Node

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `nodeKey` | stable key | R，定义内唯一 |
| `typeCode` | string | R，目录中的启用节点类型 |
| `name` | string | R |
| `device` | object/null | O，默认 null；`{deviceId,capabilityVersion}`，两个字段均 R |
| `target` | object/null | O，默认 null；`{kind,id}`，kind=LOCATION/GROUP |
| `parameters` | object | R，按节点 parameterSchema |
| `actions` | Action[] | R，无设备能力时为空 |
| `materialRefs` | stable key[] | R，引用 materialInputs.inputKey；无物料时为空 |
| `description` | string | O，默认空 |

本版设备选择为指定设备，不开放模糊“任意同类型设备”自动匹配。target 必须属于所选设备允许的位置或位置组；该节点不支持目标位置时提交 target 返回 422。

Action = `{actionKey,componentCode,parameters}`。actionKey 在节点内唯一；componentCode 来自该节点设备的能力快照；parameters 按该能力 parameterSchema。

actions 数组的顺序是调用声明顺序，不能解释为客户可任意拼接原始设备命令。仅目录声明 minActions/maxActions 允许且后台步骤模板能够确定性映射的组合可以发布；不支持的多动作组合返回 `ACTION_COMPOSITION_UNSUPPORTED`。

节点不能提交 commandTemplateId、commandAction、ACK 超时、重试次数、失败跳过策略等内部调度字段。平台根据已发布能力和安全策略生成执行步骤。

### 8.3 连线 Edge

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `edgeKey` | stable key | R，连线键空间内唯一 |
| `typeCode` | string | R，目录连线编码 |
| `sourceNodeKey/targetNodeKey` | stable key | R，引用现有节点 |
| `sourcePortKey/targetPortKey` | stable key | R，引用对应节点声明的 OUT/IN 端口 |
| `parameters` | object | R，按 EdgeType.parameterSchema |
| `label` | string | O，最多 128，默认空 |

同端口连接数量、来源类型、目标类型、环路和可达性由目录与服务器规则共同校验。条件、循环、移液和区间线不得仅凭 kind 构造参数，必须使用该 typeCode 的 Schema。

不支持的连线必须拒绝，不能降级成普通顺序线。条件规则不支持任意 JavaScript/SQL；若目录没有公开受限条件结构，则该能力不对客户开放。

### 8.4 物料输入 MaterialInput

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `inputKey` | stable key | R，稳定业务输入键 |
| `sourceNodeKey` | stable key | R，必须是支持物料来源的节点 |
| `name` | string | R |
| `categoryId` | ID | R，工艺要求的物料类 |
| `quantity` | integer | R，1～1000，表示具体物料对象数量 |
| `requiresPlacement` | boolean | R；实物来源通常为 true，由节点规则进一步约束 |

一个具体物料对象只能绑定到订单的一个输入槽，不能通过把 stockQuantity 设置为多个来替代多个物料对象。材料在后继节点的引用通过 materialRefs 关联同一 inputKey，调度器负责路径和状态推进。

inputKey 不能依据数组位置自动计算；排序变化不能改变其业务含义。平台内部 configKey 等关联键由适配层计算和保存，客户不直接使用。

### 8.5 订单参数 ParameterDefinition

`{parameterKey,name,required,schema,unit,defaultValue}`，其中：

- parameterKey 为 R 稳定键，同一工艺内唯一；name 为 R。
- schema 为 R，受限 JSON Schema，定义单个值而非整个参数集合。
- unit 为 O 可空字符串；defaultValue 为 O，仅存在时应用默认值，且必须通过 schema。
- schema 中不得引用外部 URL；数组/对象规模受公共限制控制。
- 每个参数是否必填由 schema 外的 `required` 布尔字段指定，该字段 R。

订单创建时缺失必填且无默认值的参数返回 422。有默认值时平台复制发布版本的默认值到订单快照，并在订单查询中返回实际归一化值。

### 8.6 参数绑定 ParameterBinding

固定结构 `{parameterKey,nodeKey,actionKey,targetPointer}`：

- parameterKey 引用已声明订单参数。
- nodeKey 引用目标节点；actionKey 可空，null 表示节点 parameters，否则指向该节点的动作 parameters。
- targetPointer 是相对目标 parameters 的非空 JSON Pointer，例如 `/temperature`。不允许替换整个节点、设备或目标位置。
- 同一目标参数只能绑定一次。绑定不能改变结构标识、组件代码、物料 ID 或驱动策略。
- 发布校验参数类型和目标约束；创建订单时使用实际值再次校验所有目标 Schema。
- 未被动态参数绑定的字段从发布定义固定值读取；已绑定字段在创建订单时覆盖固定占位值。
- 非必填参数既未提供也无默认值时，保留目标的发布版固定值；没有合法固定值则创建订单失败，不以 null 自动补齐。

本版不提供“前一个节点输出作为下一个节点参数”的通用脚本语法；需要此能力的节点必须在目录公开受限业务 Schema 并另行验证。变量库引用同样只允许使用节点明确声明的字段，不推定所有节点可引用任意变量。

### 8.7 布局 Layout

Layout = `{nodes,edges,viewport}`：

- nodes 为 `{nodeKey,x,y}[]`，x/y 为有限 JSON number，范围 -100000～100000。
- edges 为 `{edgeKey,renderer}[]`，renderer=STRAIGHT/BEZIER/SMOOTHSTEP/STEP。
- viewport=`{x,y,zoom}`，zoom 为 0.1～4，坐标同上。
- 三个字段均可省略，默认空数组和 `{x:0,y:0,zoom:1}`。引用不存在节点/连线时保存拒绝。
- 布局不参与执行语义，但会改变草稿 revision；已发布版布局也不可直接修改，展示端可自行保存个人视图。

## 9. 工艺管理、校验与发布

### 9.1 创建工艺

`POST /workflows`：`{externalWorkflowCode,name,description?,remark?}`。外部系列编号和名称必填，描述/备注默认空。

返回 WorkflowRecord，创建时 status=DRAFT、workflowVersion=1、revision=1、publishedAt=null、definitionHash=null；初始 definition 未设置。

WorkflowRecord 字段：

`workflowId/workflowCode/externalWorkflowCode/workflowVersion/name/status/revision/description/remark/definitionHash/createdAt/updatedAt/publishedAt`。

status 仅 DRAFT/PUBLISHED；definitionHash 为已发布执行语义 SHA-256 的小写十六进制字符串，草稿为 null；publishedAt 可空。该 hash 排除纯布局和追踪信息，由平台计算，客户视为不透明校验值。

### 9.2 查询与基础信息修改

`GET /workflows`：额外筛选 `externalWorkflowCode`、`workflowCode`、`status`、`name`（包含匹配）、`latestOnly`（默认 false）。返回 WorkflowRecord 分页。latestOnly=true 表示每系列最大的版本号，可能是草稿，不保证可用于订单。

`GET /workflows/{id}` 返回指定记录和 ETag。  
`PATCH /workflows/{id}` 仅允许 `name/description/remark`，仅 DRAFT 可修改；成功返回完整记录和新 ETag。

获取可执行版本时必须明确筛选 status=PUBLISHED 并选择版本，不能直接使用列表第一条或“最新”草稿。

### 9.3 获取与保存定义

`GET /workflows/{id}/definition` 返回 `{workflowId,workflowVersion,revision,definition}` 和该工艺记录 ETag。definition 尚未设置时为 null。

`PUT /workflows/{id}/definition` 请求就是 WorkflowDefinition；仅 DRAFT 可写。成功返回同一结构，definition 为保存后的规范化对象。

保存检查传输结构、权限、唯一键和引用存在性；允许尚未连接完成或必填业务参数未填齐的草稿。发布所需的完整业务校验由 validate/publish 执行。Schema 顶层错误、未知节点类型和未授权资源不能以“草稿”理由绕过。

全量替换对定义的更新必须是原子操作。两个用户基于同一 revision 保存，只有一个成功，另一个 412；客户端重新读取并合并，禁止直接覆盖。

### 9.4 独立校验

`POST /workflows/{id}/validate`，请求 `{}`，If-Match 指定被检查修订；不修改工艺、不生成计划、不锁定实物。

HTTP 200 的 data：

```json
{
  "workflowId": "210000000000000301",
  "workflowVersion": 1,
  "revision": 3,
  "valid": false,
  "checkedAt": "2026-11-17T08:10:00Z",
  "issues": [
    {
      "severity": "ERROR",
      "code": "PARAMETER_REQUIRED",
      "path": "/nodes/1/actions/0/parameters/temperature",
      "nodeKey": "n_heat",
      "edgeKey": null,
      "inputKey": null,
      "message": "缺少目标温度"
    }
  ]
}
```

issues 元素在错误元素基础上增加 severity=ERROR/WARNING。只有 ERROR 阻止发布，WARNING 必须展示，但本版不要求单独确认接口。验证成功不能作为资源预留，也不能代替发布时重新校验。

请求非法/无权限仍使用 4xx；HTTP 200 valid=false 表示“校验动作正常完成，业务内容不满足要求”。

### 9.5 发布

`POST /workflows/{id}/publish`，请求 `{}`，I、E。

服务端锁定被发布修订，重新完成图结构、参数、设备能力、物料类别和调度可编译性校验。失败为 422 `VALIDATION_FAILED`，附 errors；不允许部分发布。

成功返回 `{workflow: WorkflowRecord, inputSchema: WorkflowInputSchema}`，记录转 PUBLISHED、revision 增加、definitionHash 和 publishedAt 生成。所有执行依赖须固定或有可拒绝的兼容性检查。

已发布版本不可通过任何开放入口修改。同键重放原成功；用新键再次发布已发布记录返回 409 `WORKFLOW_ALREADY_PUBLISHED`，不会再占用版本号。

### 9.6 历史与新版本

`GET /workflows/{id}/versions` 返回同系列 WorkflowRecord 分页，固定按 workflowVersion 降序，不允许跨应用泄漏同编码资源。

`POST /workflows/{id}/versions` 从指定已发布版本派生：请求 `{name?,description?,remark?}`，缺失则继承源版本；I、E 检查源记录。返回新的 WorkflowRecord（201），新的 workflowId，沿用系列编码，版本号由平台分配，revision=1、status=DRAFT。

同时复制定义和稳定 nodeKey/inputKey；后续编辑不改变源版本。每个系列最多一个活动草稿，已有草稿时返回 409 `DRAFT_ALREADY_EXISTS`；同幂等请求仍返回原派生记录。

### 9.7 订单输入 Schema

`GET /workflows/{id}/input-schema` 只接受已发布记录；草稿返回 409 `WORKFLOW_NOT_PUBLISHED`。路径中的 workflowId 已指定具体版本，不额外传“最新版本”。

WorkflowInputSchema：

`{workflowId,workflowCode,externalWorkflowCode,workflowVersion,definitionHash,materialInputs,parameterDefinitions}`。后两个数组与已发布定义一致，客户端不得自行从内部 configKey 推断输入关系。

示例 data：

```json

  "workflowId": "210000000000000301",
  "workflowCode": "WF-0001",
  "externalWorkflowCode": "CUSTOMER-WF-001",
  "workflowVersion": 1,
  "definitionHash": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "materialInputs": [
    {
      "inputKey": "sample_plate",
      "sourceNodeKey": "n_input",
      "name": "待处理孔板",
      "categoryId": "210000000000000102",
      "quantity": 1,
      "requiresPlacement": true
    }
  ],
  "parameterDefinitions": [
    {
      "parameterKey": "target_temperature",
      "name": "目标温度",
      "required": true,
      "schema": {"type": "number", "minimum": 20, "maximum": 80},
      "unit": "Cel",
      "defaultValue": 37
    }
  ]
}
```

## 10. 订单创建与执行控制

### 10.1 创建订单

`POST /orders`，I。请求：

| 字段 | 类型 | 要求 |
| --- | --- | --- |
| `externalOrderNo` | string | R，应用范围唯一不可变 |
| `name` | string | R |
| `workflowId` | ID | R，已发布的具体记录 |
| `workflowVersion` | integer | R，必须与该记录一致，不能传 latest |
| `operatorId` | ID | R，已授权工艺负责人 |
| `inputMaterials` | Binding[] | R，无物料需求才可为空 |

| `concurrencyLimit` | integer | O，默认 1；SEQUENTIAL 必须 1，QUOTA 为 1～100 且不超过授权设备配置 |

Binding = `{inputKey,materials:[{materialId}]}`。inputKey 不重复；数量严格等于发布版 quantity；同一 materialId 在订单所有输入中不得重复。实物类别从服务端查询，不能信任客户传入的展示类别。

创建阶段检查发布版本、权限、输入数量和参数，不占用设备或实物。未就位物料可先绑定，但启动自检会失败。订单创建后不能通过修改工艺系列的最新版本改变本订单。

### 10.2 Order 响应与查询

Order 包含创建请求全部字段，加：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `orderId/orderNo` | string | 内部 ID、平台订单号 |
| `workflowCode/externalWorkflowCode` | string | 工艺系列关联 |
| `status` | enum | 见 10.8 |
| `revision` | integer | If-Match 使用的资源修订号 |
| `stateVersion` | decimal integer string | 公共状态、操作状态与结果摘要更新序号 |
| `planId` | ID/null | 计划 ID |
| `planState` | enum/null | PREPARED/READY/RUNNING/PAUSED/COMPLETED/FAILED/CANCELLED/FROZEN |
| `executionMode` | enum | 本版固定 REAL；测试应用仅允许指向隔离模拟环境 |
| `progress` | object | `{completed,total,percent}`；整数，percent 0～100 或 null |
| `resultStatus` | enum | PENDING/GENERATING/READY/PARTIAL/FAILED |
| `requiresAttention` | boolean | 是否需人工处置 |
| `pendingOperationId` | ID/null | 尚未完成的启动/控制操作 |
| `lastError` | object/null | `{code,message}` |
| `createdAt/updatedAt` | timestamp | 时间 |
| `startedAt/endedAt` | timestamp/null | 尚未发生为 null |

progress.total/completed 表示主流程物料对象进展，不代表设备步骤数量；total=0 时 percent=null。结果为空但生成完成仍可以 resultStatus=READY，不能用 items 空数组判断是否完成。

GET `/orders` 额外筛选 `externalOrderNo`、`workflowId`、`status`、`resultStatus`；返回 Order 分页。GET `/orders/{id}` 返回 Order 和 ETag。

后端任何影响业务编辑、控制许可的变更递增 revision；状态、进度、操作状态、结果摘要更新递增 stateVersion。同一次事务变化产生多个事件时允许共享同一 stateVersion；后续操作变化不能沿用之前的旧版本。版本字符串按数值比较，不按字典序比较；可用 BigInt 或十进制长度比较，不能转为有精度损失的 Number。

### 10.3 修改订单

PATCH 仅允许 `name/operatorId/inputMaterials/parameters/scheduleMode/concurrencyLimit/priority/remark`；仅 status=DRAFT/READY、planId=null 且无待处理操作时可用。

不允许更换 workflowId/workflowVersion/externalOrderNo。需要换工艺时新建订单。数组整体替换，并按完整订单约束重新校验。成功返回 Order 和新 ETag；自检结论随修改失效。

### 10.4 自检

`POST /orders/{id}/precheck`，请求 `{}`，E，不要求 I。仅未启动且没有已准备计划的订单可以调用。

返回：

`{orderId,revision,checkId,checkedAt,passed,checks}`；checks 数组元素 `{checkCode,severity,passed,message,resourceType,resourceId}`，后两个字段可空。检查类别至少覆盖 WORKFLOW、INPUTS、PARAMETERS、PLACEMENT、DEVICES、LOCATIONS、AUTHORIZATION。

HTTP 200 passed=false 表示检查完成但不能启动，不占用资源、不生成计划、不更改订单状态。不得把 checkId 当启动授权令牌；启动接口不接受“跳过自检”开关。

### 10.5 启动

`POST /orders/{id}/start`，请求 `{}`，I、E。

受理前检查对象归属、状态、是否已有启动操作和版本；受理后持久化 START Operation，在工作流程中完成实时自检、计划准备及启动。返回 HTTP 202，data=`{operation: Operation, order: Order}`。

HTTP 202 表示操作已可靠受理，不表示运行中，更不表示实验完成。订单 pendingOperationId 指向该操作，禁止同时编辑。

同键重试返回原操作。不同键再次启动同一订单返回 409 `ORDER_ALREADY_STARTED` 或 `OPERATION_IN_PROGRESS`，不能创建第二个计划。

START 操作的成功条件为计划获得执行许可且进入 RUNNING；仅 PREPARED/READY 时继续保持 RUNNING 操作状态。若准备失败且确认没有计划、没有指令，操作 FAILED，可在修复后以新幂等键重试；若已存在计划，则本版不允许新 START，必须查询并由平台恢复原操作/计划。

计划创建、幂等及操作记录必须具备崩溃恢复能力。结果不确定时进入 RECONCILING，不能将未知状态当作启动失败并自动重发物理动作。

### 10.6 暂停、恢复、取消

三个接口请求统一 `{reason: string}`，reason R，1～500 字符；I、E。

| 接口 | 允许前态 | 实际成功条件 |
| --- | --- | --- |
| `/pause` | 订单 RUNNING 且计划未冻结、无待处理操作 | 在支持的安全边界进入 PAUSED |
| `/resume` | PAUSED 且不存在未解决的人工阻断 | 计划重新进入 RUNNING |
| `/cancel` | DRAFT/READY/RUNNING/PAUSED | 停止后续派发，处理已在途动作并完成资源核对后进入 CANCELLED |

返回结构与 START 相同。目标设备不支持安全控制时 409 `CONTROL_NOT_SUPPORTED`，不能声称已暂停或已取消。

同一订单最多一个非终态控制/启动操作；不同请求竞争返回 409 `OPERATION_IN_PROGRESS`。本版不支持取消抢占未完成的暂停/启动操作；紧急停止必须走现场安全机制。

若物理动作已完成，取消不能撤销其结果；取消过程中自然完成实验时，操作 FAILED（`STATE_CONFLICT`），订单保留真实完成状态，不能改写为已取消。暂停或取消延迟超过预期时只能查询和告警，不能假定设备停止。

### 10.7 Operation

GET `/operations/{id}` 返回：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `operationId/orderId` | ID | 操作与订单 |
| `type` | enum | START/PAUSE/RESUME/CANCEL |
| `status` | enum | ACCEPTED/RUNNING/RECONCILING/SUCCEEDED/FAILED |
| `reason` | string/null | 启动时 null |
| `createdAt/updatedAt` | timestamp | 时间 |
| `completedAt` | timestamp/null | 仅终态有值 |
| `planId` | ID/null | 关联计划 |
| `error` | object/null | `{code,message,retryable}` |

ACCEPTED 已持久化等待处理；RUNNING 正在执行操作；RECONCILING 表示动作或资源状态需核对，不能自动重提。SUCCEEDED/FAILED 为操作终态。

START SUCCEEDED 只表示实验开始，不表示订单成功。FAILED 的 retryable=true 仅说明完成重新查询和状态检查后可以发起新的业务请求，不授权重复未知物理动作。客户端建议 2 秒查询一次，30 秒后降至 5 秒；持续未完成需告警，不用更换幂等键绕过。

### 10.8 订单与计划状态

| 公共订单状态 | 现有订单状态参考 | 语义 |
| --- | --- | --- |
| DRAFT | 0 | 已创建，未执行 |
| READY | 10 | 就绪，仍需启动实时检查 |
| RUNNING | 20 | 执行中 |
| PAUSED | 30 | 暂停已生效 |
| COMPLETED | 50 | 执行完成 |
| PARTIAL | 55 | 部分完成，须查询具体结果 |
| FAILED | 60 | 执行失败 |
| CANCELLED | 70 | 取消完成 |

最后四项为终态，不能通过本协议重启。重复实验应创建新订单和新外部订单号。

常见迁移：DRAFT→READY→RUNNING；RUNNING→PAUSED→RUNNING；RUNNING→COMPLETED/PARTIAL/FAILED/CANCELLED；未运行订单可取消。调用者可能错过短暂中间状态，不能要求必须收到每个阶段才更新界面。

FROZEN 是计划安全状态，不虚构为现有订单枚举。冻结时 Order 可能仍显示 RUNNING 或 PAUSED，但 planState=FROZEN、requiresAttention=true，所有自动控制均停止，等待授权人工处置。订单与计划应在一致性事务视图下查询；发现不可恢复的不一致返回 503 并告警，不猜测成功状态。

## 11. 执行查询、结果和文件

### 11.1 步骤、日志和异常

三类列表使用通用分页和订单归属鉴权。

| 接口 | 额外筛选 | 元素字段与排序 |
| --- | --- | --- |
| `/orders/{id}/steps` | `nodeKey`、`status` | `stepId,nodeKey,actionKey,materialId,deviceId,status,attemptCount,startedAt,endedAt,error`；按计划内生成序号升序 |
| `/orders/{id}/logs` | `level`、`nodeKey`、`occurredFrom/occurredTo` | `logId,sequence,level,eventCode,nodeKey,message,occurredAt`；sequence 数值升序 |
| `/orders/{id}/exceptions` | `resolved` 布尔、`nodeKey` | `exceptionId,code,severity,message,nodeKey,stepId,requiresManual,resolved,occurredAt,resolvedAt`；occurredAt、ID 升序 |

Step.status=`PENDING/WAITING/DISPATCHED/ACKNOWLEDGED/RUNNING/SUCCEEDED/FAILED/CANCELLED/UNKNOWN`。ACKNOWLEDGED 仅设备确认接收，不等于执行完成。step.actionKey/materialId/deviceId/startedAt/endedAt/error 可空；error 为 `{code,message}`。attemptCount 非负整数。

Log.level=DEBUG/INFO/WARN/ERROR；sequence 为十进制整数字符串；nodeKey 可空。日志仅辅助诊断，不作为状态机事实来源。

Exception.severity=WARN/ERROR/CRITICAL；nodeKey/stepId/resolvedAt 可空。本协议仅查询异常，不提供强制关闭或人工确认入口。

### 11.2 结构化结果

GET `/orders/{id}/results` 支持 `nodeKey`、`materialId`、`metricCode`、`resultVersion` 及通用分页。

返回 data=`{orderId,resultStatus,resultVersion,items,page,pageSize,total}`。resultVersion 为结果快照版本字符串，首次可不传，服务端固定本次快照；后续页必须带相同 resultVersion。结果快照在文件和结果约定保留期内可查询，过期返回 410 `RESULT_VERSION_EXPIRED`。

ResultItem：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `resultId` | ID | 结果标识 |
| `nodeKey/stepId` | string/null | 来源 |
| `materialId` | ID/null | 无物料结果可空 |
| `metricCode/name` | string | 指标编码和名称 |
| `valueType` | enum | integer/number/boolean/string/object/array |
| `value` | JSON value/null | 类型对应；缺测允许 null，需 quality 标记 |
| `unit` | string/null | 明确单位，无量纲可空 |
| `quality` | enum | VALID/INVALID/MISSING |
| `collectedAt` | timestamp | 采集时间 |
| `fileIds` | ID[] | 原始数据关联文件 |

长整型实验结果超过 JSON 安全整数范围时用 valueType=string，不得截断；具体数据精度约定在设备结果 Schema。无权限的原始字段不会出现在结果中。

resultStatus 与订单终态独立：PENDING 尚未开始汇聚；GENERATING 汇聚中；READY 全部可用；PARTIAL 部分可用；FAILED 汇聚失败。READY 不代表所有指标质量有效，应同时检查 quality。结果修正生成新的 resultVersion，并产生 results.updated 事件，不覆盖历史快照。

### 11.3 文件列表与下载

GET `/orders/{id}/files` 使用通用分页，可按 `nodeKey`、`materialId` 筛选。元素：

`{fileId,name,mediaType,sizeBytes,sha256,status,nodeKey,materialId,createdAt,expiresAt}`。

sizeBytes 为十进制整数字符串；sha256 是 64 位小写十六进制值，status=GENERATING 时两者可空；status=GENERATING/READY/FAILED/EXPIRED。nodeKey/materialId/expiresAt 可空，expiresAt=null 表示按合同保留、不设置单独过期时间，不意味着永久承诺。

GET `/orders/{id}/files/{fileId}/content`：

- 必须验证 fileId 属于该订单，且调用者具有 result.read 和订单访问权。
- READY 时返回 200 二进制流、正确 Content-Type、Content-Length 和安全的 Content-Disposition。
- 本版不承诺 Range/断点续传，服务器忽略 Range 返回完整 200，并发送 `Accept-Ranges: none`。
- GENERATING 返回 409 `RESULT_NOT_READY`；FAILED 返回 409 `RESULT_GENERATION_FAILED`；EXPIRED 返回 410 `FILE_EXPIRED`。
- 不返回任意本地路径或永久公开下载地址，不自动跳转到未经验证的外部 URL。
- 流开始前的错误使用 JSON envelope；流中断时不能再追加 JSON，客户按 Content-Length 与 sha256 检测并重新下载。

结果和文件保留期必须在接入登记单中明确，本版默认建议 90 天，但不是未签约的长期存储承诺。

### 12.1 配置与事件类型

客户提供 HTTPS 接收地址，我方受控登记 URL、订阅事件、密钥及应用绑定。每应用本版只配置一个回调地址；地址不通过订单请求传入。一个应用只能收到自身或显式授权的订单事件。

| eventType | 含义 |
| --- | --- |
| `order.created` | 订单创建成功 |

### 12.3 签名、接收与重试

发送请求：

```http
POST /customer/lab-events HTTP/1.1
Content-Type: application/json
X-Lab-Key-Id: wh-key-01
X-Lab-Timestamp: 1794904200
X-Lab-Delivery-Id: delivery_000001
X-Lab-Signature: v1={lowercase_hex_hmac_sha256}
```

时间戳为发送尝试时的 Unix 秒，不是 occurredAt。每次重投生成新的 deliveryId、时间戳和签名，eventId 及正文保持不变。正文使用 UTF-8 原始字节，不压缩。

签名定义：

```text
prefix = UTF8(timestamp + "." + deliveryId + ".")
signedBytes = prefix || rawBodyBytes
signature = lowercaseHex(HMAC-SHA256(secretBytes, signedBytes))
X-Lab-Signature = "v1=" + signature
```

secretBytes 为双方安全交付的至少 32 字节随机密钥；交付值使用 Base64 编码，计算时先 Base64 解码。不能把 Base64 文本直接当密钥。密钥轮换时使用 Key-Id 区分新旧密钥，旧密钥至少保留到约定重试窗口结束。

接收要求：

1. 限制正文大小，保留原始字节，尚未验签不要重新序列化 JSON。
2. 检查 Key-Id、签名格式、deliveryId 格式及时间戳，允许时钟偏差不超过 300 秒。
3. 计算签名并采用常量时间比较。验签成功后解析 JSON 和校验结构。
4. 按 eventId 唯一落库或可靠入队，成功后返回 200 或 204。已持久化的重复事件直接返回成功。
5. 不能先返回成功、再仅放入易丢失内存队列。客户业务处理失败在其内部重试。
6. 按 stateVersion 更新订单缓存，不让旧版本覆盖新版本；同版本不同事件仍按 eventId 分别记录，不重复触发业务动作。

签名校验示例（Node.js 标准库；只演示验签，不包括 HTTP 服务、可靠入队和去重存储）：

```javascript
import { createHmac, timingSafeEqual } from 'node:crypto';

export function verifyLabWebhook(rawBody, headers, secretBase64, nowSeconds) {
  if (!Buffer.isBuffer(rawBody)) return false;
  const timestamp = headers['x-lab-timestamp'];
  const deliveryId = headers['x-lab-delivery-id'];
  const signature = headers['x-lab-signature'];
  if (typeof timestamp !== 'string' || !/^[0-9]{1,12}$/.test(timestamp)) return false;
  if (typeof deliveryId !== 'string' || !/^[A-Za-z0-9_-]{8,96}$/.test(deliveryId)) return false;
  if (typeof signature !== 'string' || !/^v1=[0-9a-f]{64}$/.test(signature)) return false;
  if (!Number.isFinite(nowSeconds) || Math.abs(nowSeconds - Number(timestamp)) > 300) return false;
  const key = Buffer.from(secretBase64, 'base64');
  if (key.length < 32) return false;
  const expected = createHmac('sha256', key)
    .update(`${timestamp}.${deliveryId}.`, 'utf8')
    .update(rawBody)
    .digest();
  const received = Buffer.from(signature.slice(3), 'hex');
  return received.length === expected.length && timingSafeEqual(received, expected);
}
```

调用者先按 `x-lab-key-id` 从服务端配置中找到密钥；未知 keyId 直接拒绝，不从请求加载密钥。去重至少保留 30 天，长期业务副作用还需按订单外部号与业务操作建立持久化唯一约束。

投递策略基线：

| 项目 | 约定 |
| --- | --- |
| 成功判定 | 任意 2xx，无需业务响应体 |
| 连接/整次超时 | 3 秒/5 秒 |
| 自动尝试 | 首次立即；失败后依次等待 10秒、30秒、1分钟、5分钟、15分钟、1小时、3小时、6小时、12小时，共最多 10 次 |
| 可重试 | 网络失败、408、429、5xx |
| 不自动重试 | 其他 4xx、3xx；立即标记投递失败并告警，不跟随重定向 |
| Retry-After | 429/503 可提供整数秒；等待取该值与本次退避较大者，最大 12 小时 |
| 最终失败 | 保留事件，告警，允许我方管理端人工补发；客户也可补拉 |

Webhook 是至少一次投递，无全局顺序保证。自动投递耗尽不影响实验状态，不触发重复实验。

### 12.4 事件补拉

`GET /events?cursor={opaqueCursor}&limit=100`

| 参数 | 要求 |
| --- | --- |
| `cursor` | O；缺失从当前保留窗口最早可见事件开始；取字面值 `latest` 时仅建立当前已提交尾部游标并返回空 items |
| `limit` | O；1～200，默认 100 |

data=`{items:Event[],nextCursor,hasMore,retentionStartsAt}`。nextCursor 永不为空，即使 items 为空也返回可继续使用的游标。hasMore 表示本次读取时已有更多可见事件，不表示之后不会有新事件。

- 游标绑定应用、租户和事件读取范围，不允许跨应用复用；错误作用域返回 400 `CURSOR_INVALID`。
- 按已提交外部事件日志顺序推进，不按 occurredAt 排序，不直接把数据库最大 ID 当作已完整提交水位，避免并发事务导致漏事件。
- 客户先可靠处理本页所有事件，再保存 nextCursor；失败重读允许重复，不允许跳过。
- 超过至少 30 天留存窗口返回 410 `CURSOR_EXPIRED`，不能静默从当前时间开始。
- 不支持任意时间范围和事件类型筛选，避免过滤后游标语义不一致；客户端可本地筛选。

游标过期恢复：先调用 cursor=latest 保存新尾部游标，再分页核对所有需要维护的订单及其结果，随后从该尾部游标补拉期间新增事件。因为普通列表不是快照，对非终态订单须重复核对至稳定；不要只靠 updatedAt 单页扫描认定恢复完成。

| 情况 | 客户行为 |
| --- | --- |
| GET 网络超时/5xx | 指数退避重试，建议 1、2、4、8 秒，最多 4 次后告警 |
| 写请求响应丢失 | 原键原内容重试；根据外部编号查询资源或 operationId 查询 |

| 409 REQUEST_IN_PROGRESS | 原键原内容，按 Retry-After 等待 |

| 422 校验失败 | 修正参数或现场条件；不得无限重试 |

| RECONCILING/FROZEN | 停止自动执行请求，交由授权人员核对 |

同键重放结果可能是过去的状态，客户端随后 GET 获取当前状态。不能依靠幂等响应判断订单仍处于创建时的 DRAFT 状态。

## 14. 完整调用示例

### 14.1 调用前提

示例链路使用第 8.8 节定义。所有 ID、目录编码和物理尺寸仅作说明，不得直接向真实设备提交。客户需先有已授权应用、负责人及设备，并完成物料类适配核验。

下文 HTTP 示例省略 Host，所有业务请求都必须带 Bearer 令牌。响应表中省略 envelope，只说明 data；真实 response 必须按第 2.3 节解析。

### 14.2 主数据与物料

1. 获取专用应用令牌。
2. GET `/operators?purpose=ORDER_OWNER` 获取负责人。
3. GET `/material-types?externalTypeCode=PLATE`，没有时按 5.2 创建。
4. GET `/material-categories?externalCategoryCode=CAT-PLATE-96`，没有时按 5.3 创建并安排物理核验。
5. POST `/materials`，使用第 6.1 节请求和幂等键 `material_MAT_20261117_001`。
6. GET `/locations?categoryId=210000000000000102&available=true` 选择授权位置。
7. GET 物料详情获取最新 ETag，再确认现场已放入指定槽位。

```http
POST /openapi/v1/materials/210000000000000001/placement-confirmations HTTP/1.1
Authorization: Bearer EXAMPLE_TOKEN_NOT_VALID
Content-Type: application/json
Idempotency-Key: placement_MAT_20261117_001
If-Match: "rev-1"

{
  "locationId": "210000000000000203",
  "containerPosition": "1-1",
  "postureDegrees": "0",
  "confirmedByOperatorId": "210000000000000103",
  "observedAt": "2026-11-17T08:00:00Z",
  "remark": "示例，实际时间必须为真实确认时间"

```

上例入库位置 203 与动作目标位置 202 可以不同，但必须由现有调度运输能力支持。不能凭接口示例假设机械臂自动具备两者间的可达路径。

### 14.3 获取组件并设计工艺

1. GET `/workflow-capabilities`，保存 catalogVersion。
2. GET `/devices?nodeTypeCode=device_action`，选择设备。
3. GET `/devices/210000000000000201/capabilities`，保存 capabilityVersion，检查 heat 能力及参数。
4. GET `/locations?deviceId=210000000000000201`，获取实际动作目标。
5. 创建工艺草稿：

```http
POST /openapi/v1/workflows HTTP/1.1
Authorization: Bearer EXAMPLE_TOKEN_NOT_VALID
Content-Type: application/json
Idempotency-Key: workflow_CUSTOMER_WF_001

{
  "externalWorkflowCode": "CUSTOMER-WF-001",
  "name": "孔板恒温工艺",
  "description": "客户系统设计"
}
```

返回 workflowId=`210000000000000301`、workflowVersion=1、revision=1。

6. PUT `/workflows/210000000000000301/definition`，正文使用第 8.8 节定义，带 `If-Match: "rev-1"` 和新幂等键；成功获得 revision=2。
7. POST `/workflows/210000000000000301/validate`，正文 `{}`、If-Match 为 rev-2；valid=false 时展示 issues，修改保存后再校验。
8. POST `/workflows/210000000000000301/publish`，正文 `{}`、If-Match 使用最新修订、新幂等键；成功转 PUBLISHED，取得固定版本和输入 Schema。

后续修改时创建新版本，不能 PUT 已发布工艺。

### 14.4 创建、启动并跟踪订单

1. GET `/workflows/210000000000000301/input-schema`。
2. POST `/orders`，使用第 10.1 节请求和幂等键 `order_ORDER_20261117_001`。
3. GET 订单获得 ETag；POST `/orders/{id}/precheck`，正文 `{}`，检查 passed。
4. 再次 GET 订单确认没有并发变更，用最新 ETag 启动。

```http
POST /openapi/v1/orders/210000000000000401/start HTTP/1.1
Authorization: Bearer EXAMPLE_TOKEN_NOT_VALID
Content-Type: application/json
Idempotency-Key: start_ORDER_20261117_001
If-Match: "rev-1"

{}
```

202 响应示意：data.operation.operationId=`210000000000000601`，status=ACCEPTED；data.order.pendingOperationId 与之相同。

5. GET `/operations/210000000000000601`，SUCCEEDED 后只表示开始运行。
6. 接收 order.started 等事件，同时周期查询订单进行对账。
7. 收到 order.completed 后检查 resultStatus；GENERATING 时继续等待或查询，不能立即报“结果下载成功”。
8. GET `/orders/{id}/results`，后续分页固定 resultVersion。
9. GET `/orders/{id}/files`，仅下载 READY 文件并验证长度与 sha256。

## 15. 安全、兼容与验收

### 15.1 服务端必须实现

- 所有外部输入使用独立 DTO 和白名单；禁止将请求直接绑定包含系统状态的内部 Entity。
- 对关联资源逐项检查权限，不仅检查最外层订单或工艺 ID。
- 创建记录、外部映射、幂等记录和状态变更保证可恢复的一致性。
- 发布版本、内部模板依赖和输入键必须稳定，禁用组件时明确拒绝新执行。
- 启动与修改、位置确认与占用、取消与设备派发要处理并发竞争。
- 设备回执可能重复、迟到或缺失，不能仅凭 QoS/Outbox 声称物理动作 exactly-once。
- 未知动作结果禁止自动盲重试，必须核对或冻结。
- SQL 参数化，Webhook URL 防 SSRF，文件路径不可由客户任意指定。
- 外部通知与设备指令队列隔离；客户回调故障不能阻塞调度。
- 日志脱敏，密钥不进源码；审计关联应用、负责人、订单、计划及请求标识。

### 15.2 兼容性策略

- `/v1` 内只增加可选字段或新增接口，不静默改变已有字段类型、单位、必填性和状态语义。
- 新增事件类型视为扩展；客户应持久化未知类型并告警，可安全确认接收，不能触发未知业务动作。
- 未知业务状态不得映射为成功或可启动。增加影响控制的枚举前需要协同升级。
- 工艺 schemaVersion、catalogVersion、设备 capabilityVersion、发布版本分别管理，不混用一个版本号。
- 停用目录/能力需标注原因并提供迁移指引；安全原因紧急禁用时可立即阻断新执行，但必须告警。
- 正式生产发布、弃用及保留窗口通过双方变更流程确认，不以草稿日期作为生效日期。

| 订单实物绑定 | OrderMaterialBindingCompiler | inputKey 转换内部 sourceNodeKey/configKey，不由客户拼接内部 v2 |
| 计划准备 | SchedulePlanPreparerImpl | 稳定启动键、应用作用域、异步操作和恢复 |
| 执行控制 | ScheduleRunOrchestratorImpl | 对象权限、控制操作状态、真实完成判定 |
| 监控与结果 | 订单快照、步骤、日志、数据下载 | 稳定公共状态、结果快照及文件授权 |
| 外部响应 | OpenApiResponse | 成功码沿用 SUCCESS；补齐 errors、HTTP 状态与统一追踪 |

### 16.2 最新 DTO 与本文目标契约差异

本次只读检查发现新增 openapi DTO 和支持类。以下差异必须在实现与协议评审时收敛，不能直接宣称当前 DTO 已符合本文。

| 当前 DTO/字段 | 本文目标 | 处理要求 |
| --- | --- | --- |
| externalMaterialCode / externalWorkflowCode / externalOrderNo | 同名 | 沿用现有外部编号命名 |
| 物料 categoryCode | categoryId | 通过主数据查询获得 ID；若保留编码入口需明确互斥及解析规则，不接受含糊双字段 |
| 物料创建 locationCode/containerPosition | 独立就位确认 | 登记与实物位置确认分离，不能创建即默认物理就绪 |
| WorkflowCanvasRequest.canvas/baseVersion | WorkflowDefinition 与 If-Match | 分离协议定义、修订和发布版本；不要把内部画布 JSON 当长期契约 |
| OrderCreate.workflowCode/workflowVersion | workflowId/workflowVersion | 显式绑定具体版本记录，系列编码用于展示和查找 |
| OrderCreate.operatorCode | operatorId | 从授权负责人查询解析，明确人机身份 |
| inputMaterials.sourceNodeKey/configKey/externalMaterialCodes | inputKey/materials[].materialId | 通过已发布输入 Schema 和物料查询完成绑定 |
| ExecuteRequest.requestId | Idempotency-Key 与独立追踪 requestId | 幂等键不能与每次不同的追踪标识混用 |
| OpenApiResponse 仅 code/message/data/requestId | 增加结构化 errors 及正确 HTTP 状态 | 保留兼容成功格式，补齐失败定位 |

这是目标协议的独立评审稿，不要求正在开发的代码未经确认立即改名。若当前 DTO 已被客户实际使用，须先确定迁移版本或兼容适配策略，禁止直接破坏既有调用。

### 16.3 相较可行性方案的明确化

- 统一外部编号名称，不再混用 externalId、externalCode、externalNo。
- workflowId 明确为具体版本记录；新版本创建新 ID，工艺系列编码保持不变。
- 物料规格并入物料类，增加物理适配核验状态；不把声明规格等同于设备安全认可。
- 新增变量目录、位置组、定义读取、版本列表和操作查询，支持客户完整设计器。
- 认证、错误 envelope、异步操作、目录快照、结果快照和 Webhook 验签由建议细化为目标契约。
- 取消了“直接通过当前后台 CRUD 即可完成第三方接入”的隐含假设。

**文档完成不等于接口上线。双方批准目标协议、实现并通过验收后，才能将版本状态从 draft 改为正式发布。**

### 17.01 获取访问令牌

**请求方式：POST**  
**请求地址：`https://lab-api.example.com/oauth/token`**  
**请求头：** 必填 `Authorization: Basic {Base64(client_id:client_secret)}`；必填 `Content-Type: application/x-www-form-urlencoded`。  
**权限：** 已登记且启用的应用凭据。无路径参数、无 Query、无 JSON Body。

| 位置 | 参数 | 类型 | 必填 | 默认值/说明 |
| --- | --- | --- | --- | --- |
| Form | grant_type | string | 是 | 固定 client_credentials |

client_id/client_secret 位于 Basic 头，不作为 Query 发送。

```http
POST /oauth/token HTTP/1.1
Host: lab-api.example.com
Authorization: Basic {BASE64_CLIENT_CREDENTIALS}
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials&scope=resource.read%20workflow.read
```

**响应：** 200，顶层字段 access_token/token_type/expires_in/scope，见 3.1；没有 data 外壳。凭据错误 401 invalid_client，授权范围错误 400 invalid_scope。

### 17.12 创建物料类及规格

**请求方式：POST**  
**请求地址：`https://lab-api.example.com/openapi/v1/material-categories`**  
**请求头：** 必填 `Authorization: Bearer {access_token}`、`Content-Type: application/json`、`Idempotency-Key: {幂等键}`。  
**权限：** `masterdata.write`。无 Path、无 Query，不要求 If-Match。

| 位置 | 参数 | 类型 | 必填 | 默认值/说明 |
| --- | --- | --- | --- | --- |
| Body | externalCategoryCode | string | 是 | 外部物料类编号，应用范围唯一 |
| Body | typeId | string | 是 | 已授权启用的物料类型 ID |
| Body | name | string | 是 | 1～128 字符 |
| Body | brandModel | string | 否 | 默认空，最多 128 字符 |
| Body | specification | object | 是 | 固定规格对象，不能传 JSON 字符串 |
| Body | specification.heightMm | decimal string | 是 | >0，单位 mm |
| Body | specification.pickHeightMm | decimal string | 是 | >=0 且不大于 heightMm |
| Body | specification.hasLid | boolean | 是 | 是否带盖 |
| Body | specification.lidPickHeightMm | decimal string/null | 条件必填 | 带盖时必填且>=0；无盖时省略或 null |
| Body | specification.sealable | boolean | 是 | 是否可封膜 |
| Body | specification.capacityRows | integer | 是 | 1～1000，物料内部容量行数 |
| Body | specification.capacityColumns | integer | 是 | 1～1000，物料内部容量列数 |
| Body | description | string | 否 | 默认空，最多 2000 字符 |
| Body | remark | string | 否 | 默认空，最多 2000 字符 |

```http
POST /openapi/v1/material-categories HTTP/1.1
Host: lab-api.example.com
Authorization: Bearer EXAMPLE_TOKEN_NOT_VALID
Content-Type: application/json
Idempotency-Key: doc_category_create_001

{
  "externalCategoryCode":"CAT-PLATE-96",
  "typeId":"210000000000000101",
  "name":"96孔板",
  "brandModel":"CUSTOMER-MODEL-A",
  "specification":{
    "heightMm":"14.5",
    "pickHeightMm":"8.0",
    "hasLid":false,
    "lidPickHeightMm":null,
    "sealable":true,
    "capacityRows":8,
    "capacityColumns":12
  },
  "description":"示例规格，须现场核验",
  "remark":""
}
```

**响应：** 201，完整 Category，含 categoryId、平台 code、handlingStatus=PENDING；Location 指向物料类详情。创建成功不代表已完成机械适配核验。

### 17.13 查询变量库

**请求方式：GET**  
**请求地址：`https://lab-api.example.com/openapi/v1/variables`**  
**请求头：** 必填 `Authorization: Bearer {access_token}`。  
**权限：** `masterdata.read`。无 Path、无请求体。

| 位置 | 参数 | 类型 | 必填 | 默认值/说明 |
| --- | --- | --- | --- | --- |
| Query | page | integer | 否 | 1 |
| Query | pageSize | integer | 否 | 20，1～100 |
| Query | updatedFrom | timestamp | 否 | 更新时间起点 |
| Query | updatedTo | timestamp | 否 | 更新时间终点 |
| Query | code | string | 否 | 变量编码精确匹配 |
| Query | valueType | string enum | 否 | integer/number/boolean/string/array/object |
| Query | enabled | boolean | 否 | 启用状态 |

```http
GET /openapi/v1/variables?valueType=number&enabled=true&page=1&pageSize=20 HTTP/1.1
Host: lab-api.example.com
Authorization: Bearer EXAMPLE_TOKEN_NOT_VALID
```

**响应：** 200，变量分页；包含 variableId、code、valueType、unit、defaultValue 等，完整字段见 5.4。该接口不返回其他订单的运行变量，也不能写入变量值。
