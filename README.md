# OpenWetLab

用一句话描述实验，由 AI 写出设备操作方案，人在网页上核对、批准，再由程序控制实验岛上的设备执行。

现在的实验岛（厂商网关 GW_001）有：PCR 仪、恒温振荡模组、六轴机械臂（含转向台）、料架。同一套软件既能接真机，也能在电脑上跑一座**虚拟实验岛**，用来练习和测试。

| | 虚拟岛 | 真机 |
|---|---|---|
| 设备 | 程序模拟，耗时按实测校准 | 实验室里的真设备 |
| 用途 | 熟悉流程、试新任务、开发测试 | 真实实验 |
| 数据 | `runs/virtual/` | `runs/real/` |

两者的数据完全分开，互不影响。

---

## 一、安装（只做一次）

需要 macOS 或 Linux，以及 [uv](https://docs.astral.sh/uv/)。

```bash
git clone git@github.com:Bingqi-Huang/OpenWetLab.git
cd OpenWetLab
uv sync
cp .env.example .env      # 然后编辑 .env
```

`.env` 里要填：

| 配置 | 用途 |
|---|---|
| `LLM_MODEL`、`LLM_BASE_URL`、`LLM_API_KEY` | AI 用的模型。任何 OpenAI 兼容接口都可以，格式如 `openai:gpt-4o` |
| `MQTT_PASSWORD` 等 | 连真机才需要，向实验室管理员要 |

`.env` 不会进版本库，不要把 key 写进别的文件。

---

## 二、启动

开三个终端，都先进入仓库目录。**所有命令都要从仓库根目录运行。**

```bash
# 1. 实验岛服务：唯一控制设备的程序
uv run wetlab serve --mode virtual

# 2. AI（协调者和操作员），会调用模型、产生费用；只看网页可以不开
uv run wetlab agents --mode virtual

# 3. 网页
WETLAB_MODE=virtual uv run streamlit run wetlab/app/web/main.py --server.address localhost
```

浏览器打开 <http://localhost:8501>。页面顶部会显示当前连的是“虚拟岛”还是“真机”。

连真机时，把三处的 `virtual` 都换成 `real`。真机前请先读第五节。

停止：每个终端按 `Ctrl+C`。想让某座岛从头开始，停掉三个程序后删掉 `runs/virtual/`（或 `runs/real/`）。

## 三、网页怎么用

网页有两个页面。

### 实验岛

从上到下：

1. **需要您处理**：待审阅的方案、AI 的提问。
2. **冻结说明**（只在冻结时出现）：原因和处理表单，见第四节。
3. **正在执行**：当前方案的进度。
4. **台面与器皿**：登记、更正、取走孔板。
5. **设备**：各设备的读数和是否在线。

**登记孔板**是开始实验前必须做的：编号、类型、位置（下拉框选，例如“料架 1-3”）、板里装了什么（名称、孔位、体积，可留空）。系统只认账本，**登记的位置必须和实物一致**；实物挪动后用“更正位置”改过来。

### 任务

左边是全部任务，右边是选中的任务。每个任务有四个视图，需要您处理的那个会亮起 ●：

| 视图 | 做什么 |
|---|---|
| 对话 | 看 AI 的提问和进展，回答问题、留言 |
| 方案 | 看每一步的中文说明和预演结论；到现场逐项勾选核对项，填名字，点“批准”；不对就写意见“退回” |
| 执行 | 看进度；暂停、继续、全部停止、终止实验 |
| 报告 | 每一步的结果、每块板的经历，可下载 |

### 一次完整的实验

1. “实验岛”页登记孔板，例如 `LW-001`，放在料架 1-3，内容填 `菌落 A`。
2. “任务”页 → ＋ 新建任务，用一句话写要求，例如：
   > 把菌落 A 放进 PCR 仪器，37℃ 保持 60 秒（不开热盖，孔内 25 µL），完成后把板放回原来的位置。
3. 等一两分钟，“方案”视图亮起 ●。读一遍步骤和预演结论，到现场核对，填名字，批准。
4. 切到“执行”看进度。
5. 结束后在“报告”里查看。

写任务时直接说样品名、温度、时间、体积就行，不用写板号和机械臂点位，AI 会从账本里找。高于 45℃ 的程序 AI 会自动加上热盖加热（常用 105℃）。

### 不用 AI，直接提交手写方案

```bash
uv run wetlab labware place LW-001 96孔PCR板 rack:1-3 --mode virtual
uv run wetlab submit sops/pcr_37c_30s.json --mode virtual
```

然后在网页上审阅、批准。`sops/` 下有现成的方案可参考。

## 四、出问题时

| 情况 | 怎么做 |
|---|---|
| 机械臂动作不对 | **按现场的物理急停按钮。** 机械臂运动的约 1 分钟里，软件发的停止指令要排队，停不住它 |
| PCR 或振荡要停 | “执行”视图 → 全部停止。停止后方案不能继续，剩下的步骤由 AI 出修订方案、人再批准 |
| 页面变红，显示“冻结” | 系统发现情况不明，已停止发任何动作。先到现场看，再到“实验岛”页选结论：这一步已完成 / 没完成 / 终止实验。如果那一步是搬运，还要选板现在在哪 |
| 关门后热盖没压下 | 通常是板没放进 PCR，去现场看 |
| 启动时冻结，原因是某台设备超时 | 那台设备掉线了，例如振荡器报“串口未打开”。恢复设备和网关后，重启三个程序 |
| 网关被重启 | 心跳断开约 10 秒后系统会冻结，等网关恢复后按上面处理 |

设备没有完成某一步时，系统不会自动重试，这是有意的：重发可能让设备动两次。

## 五、用真机之前

1. 和厂商约好：使用期间**不重启网关、不改设备登记、不用他们的调度系统发指令**。
2. 有人站在机械臂急停按钮旁。
3. 板的实际位置和网页上的登记一致；PCR 里没有别的板。
4. 每份方案都要人批准后才执行，批准前到现场按清单核对。
5. 先用 `uv run wetlab doctor --mode real` 检查：网关是否在线、状态是否新鲜、有没有设备报错。

真机上现在能做的：PCR 开关门、跑自定义温度程序（4～99℃）、热盖加热；振荡（定时或连续，200～3000 rpm）；机械臂在料架 1-2、1-3、PCR、振荡器之间搬板（转向台由网关在搬运中自动使用）。还不能做：移液和加样（要人工）、任何测量。

### 示教点位更新后

现场重新示教机械臂点位后，从网关导出点位文件，然后：

```bash
uv run wetlab points import 新文件.json
```

它会列出和当前版本的差异，确认后存进 `island/GW_001/vendor/`，并更新 `island/GW_001/positions.json`。这个命令只改本地文件，不会向网关发送任何东西。导入后重启服务。

## 六、给开发者

| 位置 | 内容 |
|---|---|
| `wetlab/lab/` | 实验岛：设备定义与互锁、虚拟设备、MQTT 后端、方案的校验和预演、数据库、常驻服务。不依赖任何大模型库 |
| `wetlab/agents/` | 协调者和操作员（LangChain / LangGraph） |
| `wetlab/app/` | 命令行 `wetlab` 和网页 |
| `island/GW_001/` | 这座岛的位置表和网关导出的示教点位 |
| `LAB.md` | 给 AI 看的现场规矩 |
| `sops/` | 现成方案 |
| `captures/` | 真实设备的 MQTT 录制，用于回放测试 |
| `docs/spec/` | 设计文档：01 通信规则，02 设备手册（自动生成），03 华大 P8 接口，04 总体架构与开发计划，05 Opentrons Flex 接入 |

测试（不连任何真机，不调真实模型）：

```bash
uv run pytest --deselect tests/agents/test_real_llm.py --deselect tests/agents/test_real_llm_sample_pcr.py
uv run lint-imports
```

`tests/agents/test_real_llm*.py` 会调用 `.env` 里的真实模型，产生费用，只在需要时单独运行。

开发前请先读 `docs/spec/04_总体架构与开发计划.md` 的第 0 节和第 12 节（代码规则）。
